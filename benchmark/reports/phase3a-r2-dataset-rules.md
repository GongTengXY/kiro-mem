> 日期：2026-08-04
>
> 状态：**冻结于生成任何 query 之前。** 这是本文存在的全部意义——先定纪律，再出题，再预检。
>

> `bigramAux` 保持关闭。本轮（R2）是**新实验轮次**，不是对 3A 结果的补救。

## 1. 为什么需要这两份数据集

### 1.1 「两腿都命中」校准集

Gate A 冻结的 Phase 2 校准集有 121 条，**全部 `ftsCount = 0`**。这对 2B 是正确的（它要测的就是
零关键词命中时语义腿能不能独立召回），但对任何**融合层**改动是结构盲区：单腿页面上，
改 `bigramWeight` 或改「bigram 是否给已有候选投票」都不产生可观测差异。

3A 的三条根因里有两条落在融合层：

- §5.2 误召回主体是 `hybrid`——bigram 给已有语义候选加了第三票，把它从页外推进页内；
- §5.3 等权融合让「命中几个两字词」与 bm25、cosine 同权，q14 掉名次、q04 升名次，方向不可控。

这两条在 121 条零命中集上**永久不可测**。所以 R2 的第一件事是造一份两腿都有候选的集合。

### 1.2 扩充的 empty / hard-negative 集

既有 expected-empty 只有 5 条，2D 基线恰好停在均值 1.00 / 门槛 ≤1，零余量。Gate E 维持不豁免，
理由是「事后因为样本少而放宽门槛，会破坏本轮全部 arm 的可比性」，并指定正确做法：

> 下一轮开始前扩充并冻结更大的 empty / hard-negative 集，再预登记新门槛。
> **不能用结果出来后的 54 条集合替换既有连续性锁。**

因此：**既有 5 条永久保留、继续作为连续性锁，新增集合是新增的第二道门槛，不是替换。**

## 2. 出题纪律（本节是硬约束）

### 2.1 只能从事实出题

query 与 gold ID 一律从 `benchmark/dataset/turns.json` 的 `annotation` 事实生成。

**禁止**从任何 arm 的返回结果反推 query。具体禁止的做法：

- 看某个 arm 返回了 t05，然后为 t05 编一条能命中它的 query；
- 看哪些 query 让某个候选策略表现好，据此增删；
- 用 cosine 值、FTS 名次、bigram 名次或最终页面内容挑选或删除 query。

### 2.2 预检只能看「腿在不在」，不能看「排得好不好」

允许的预检输出：某条 query 在某条腿上**有没有候选**、候选里**有没有包含 gold**。

禁止用于选择的量：cosine 数值、bm25 名次、bigram 名次、融合分、最终返回页、hit@5、MRR。

### 2.3 分层由预检**判定**，不由出题意图决定

我出题时会带一个意图分层（见 §3），但**实际分层一律取预检结果**。一条 query 若落在意图之外
的层，**留在它实际所属的层**，不删、不改题面去凑意图。这条是为了避免「改到符合我预期」这种
形状的挑选。

### 2.4 淘汰只允许两个理由，且必须留档

| 允许淘汰的理由 | 说明 |
| --- | --- |
| gold 标注站不住 | 依据 `annotation` 判断这条 query 问的事情该 turn 其实没做过 |
| 与已有 query 重复 | 题面或考查点与主集里某条实质相同 |

**不允许**以「这条让指标不好看」「这条命中太多」「这条 cosine 太低」为由淘汰。

所有未进主集的候选连同淘汰理由一起写进 `*-eliminated.json`，与主集同批冻结。

### 2.5 中文 query 的英文派生值一次性生成并冻结

`semantic_query_en` 在任何 arm 运行前一次生成、写入数据集、算 checksum。与 Phase 2 校准集同一
纪律：派生值若能在轮次中间重新生成，它就成了一个隐藏自变量。

## 3. 「两腿都命中」校准集：分层定义

四层，按 Gate E 指定的形状。`FTS` 指 trigram 腿，`bigram` 指 CJK 两字词辅助腿，
`semantic` 指 `semantic-en-v1` 向量腿（cosine > 0.197）。

| 层 | 定义 | 它能测什么 |
| --- | --- | --- |
| **S1** | FTS ✓ + semantic ✓ + bigram ✓ | 三票齐全时 bigram 加票是**改善**还是**破坏**已有排序。3A §5.3 的 q14 就是这个形状 |
| **S2** | FTS ✓ + semantic ✓ + bigram ✗ | 对照层。bigram 腿不参与时的融合基线，用来隔离「bigram 加票」这个变量 |
| **S3** | FTS ✗ + semantic ✓ + bigram ✓ | bigram 提供词面锚点、语义腿佐证。3A §5.2 误召回的**正向对偶**：同一机制在相关记录上的表现 |
| **S4** | semantic ✗ + bigram ✓（FTS 任意） | bigram 单独发现。`bigramOnlyLimit` 唯一能约束的那一类，也是唯一无语义佐证的线索 |

### 3.1 一条结构约束，直接影响 S2 怎么出题

3A 实测出一个结构性事实（`phase3a-submission.md` §7.1）：

> 含 query 中文三字窗口的记录**必然**含该窗口里的两字词。

所以对纯中文 query，**FTS 命中 ⟹ bigram 命中**，S2 在纯中文题面上不可构造。S2 的 FTS 命中
必须来自**非 CJK 单元**——标识符、路径、版本号、英文术语，例如 `FTS5`、`launchd`、
`src/db/index.ts`、`RRF`、`q8`、`bun test`、`scope_key`。

这不是取巧，而是 S2 唯一可能的形状；把它写在这里，是为了让复核者能验证 S2 的题面确实按这条
约束构造，而不是碰巧。

### 3.2 规模目标

每层至少 8 条，合计至少 32 条。S4 预计最难凑（要求语义腿**不**过 floor），若某层不足 8 条，
如实报出实际条数与原因，不为凑数改题面。

### 3.3 gold 标注口径

沿用既有数据集：`expect` 是数据集 turn id 数组，判定依据只能是该 turn 的 `annotation`
（`request` / `title` / `summary` / `outcome` / `learned` / `concepts`）。一条 query 可以有多个
gold；多 gold 时 R-precision 的截断点跟着 gold 数走，与既有 harness 一致。

## 4. 扩充 empty / hard-negative 集：分层定义

新增至少 30 条，四层覆盖 Gate E 指定的形状。全部 `kind: 'empty'`、`expect: []`。

| 层 | 定义 | 目的 |
| --- | --- | --- |
| **N1 完全无关** | 与软件工程无关的日常问题 | 基础误召回底线 |
| **N2 近邻未做** | 技术上相近、但本项目**确实没做过**的事 | 语义腿最容易误召回的形状 |
| **N3 通用两字词噪声** | 刻意含「配置」「发布」「处理」「服务」「数据」「测试」等高 DF 两字词 | **直接瞄准 3A §5.1 的失败机制**。这一层是 R2 新增的核心 |
| **N4 中英文混合** | 同时覆盖 bigram 触发（含 CJK）与不触发（纯英文）两种情况 | 中立性锁的负面对照 |

### 4.1 N2 与 N3 的标注必须能自证「项目没做过」

每条写明依据：这条问的事情在 26 条 primary Observation 里找不到对应 `request` / `outcome`。
不能只写「我认为无关」。N3 尤其要说清：它含的高 DF 两字词会命中哪些记录，而那些记录为什么
**不**回答这条 query。

### 4.2 既有 5 条的地位

`q19` `q21` `q22` `q23` `q24` **永久保留**，继续作为连续性锁，门槛沿用 2D 读数
（均值 ≤1.00、最坏 ≤2）。新增集合是**并列的第二道门槛**，两道都要过。

## 5. 冻结与复核流程

```text
本文冻结（已完成，生成任何 query 之前）
   │
   ▼
生成两份数据集 + 淘汰清单 + 英文派生值
   │
   ▼
预检（只看腿在不在）→ 实际分层 → 覆盖统计
   │
   ▼
冻结：写入 checksum
   │
   ▼
提交复核：成员清单 / gold 标注 / 生成脚本 / prompt / checksum / 预检统计
   │
   ▼
复核通过 ──► 才能追加新判据
   │
   ▼
判据冻结 ──► 才能运行新 arm
   │
   ▼
策略冻结 ──► 才能运行 heldout / validation / 独立审计集
```

任何一步跳过，后面的读数都不作数。
