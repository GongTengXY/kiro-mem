## 0. 结论

**要验的那件事通过了：把 `semantic_en` 塞进同一次压缩响应，没有让摘要质量退化。**
三轮实测事实召回均值 **0.948**（旧基线 3 次均值 0.935）、文件召回 100%、fallback 0、
JSON repair **0 次**、幻觉文件与虚构完成 0。

同时拿到一个比离线探针强得多的可靠性读数：**记录侧英文派生值三轮都是 30/30 ready，
0 pending / 0 failed（合计 90/90 个 turn）**。

出现一处门槛未通过：`heldout R-precision` 三轮读 33.3% / 50.0% / 33.3%，门槛 35%。
已归因：**与本阶段的协议改动无关**（raw 对照读同一个 33.3%），成因是 RRF 的一个既有
平局规则，见 §3。按纪律不调阈值、不在本阶段改融合层，作为阶段 2 的输入登记。

## 1. 摘要质量：与改造前基线逐项对比

改造前基线取 `acp-variance.md`（3 次运行，commit `a47b9d6`，prompt 里没有 `semantic_en`）。
ACP 输出每轮都会波动，所以对比用 **min 与均值一起看**，判据在跑之前写死：不得低于旧 min。

| 指标 | 旧均值 | 旧 min | 本轮均值 | 本轮 min | 判据 | 结果 |
| --- | ---: | ---: | ---: | ---: | --- | :--: |
| 关键事实召回 | 0.9352 | 0.9167 | **0.9481** | 0.9222 | ≥ 0.9167 | ✅ |
| 关键文件召回 | 1.0000 | 1.0000 | **1.0000** | 1.0000 | ≥ 0.95 | ✅ |
| memory_type 一致率 | 0.7222 | 0.7000 | 0.7000 | 0.7000 | ≥ 0.7000 | ✅ |
| outcome 非空率 | 1.0000 | 1.0000 | **1.0000** | 1.0000 | ≥ 0.95 | ✅ |
| fallback 数 | 0 | 0 | **0** | 0 | = 0 | ✅ |
| 幻觉文件 turn 数 | 0 | 0 | **0** | 0 | = 0 | ✅ |
| 虚构完成 turn 数 | 0 | 0 | **0** | 0 | = 0 | ✅ |

两条要点：

- **JSON 没有更容易坏。** 三轮 `repairs = 0`、`parseFallbacks = 0`、`contaminations = 0`。
  这是本次最直接的担忧（输出多了一个五字段对象，可能撑爆 16KB 读上限或让模型更容易返回
  坏 JSON），实测没有发生。
- **`memory_type` 一致率落在旧区间的下沿**（0.700 = 旧 min，旧均值 0.722，三轮 sd 为 0）。
  它没有跌破判据，但也没有余量，且三轮完全一致这件事本身说明它不是随机波动。**不宣称
  它没有受影响**——n=3、单条 turn 权重 3.3pp，这个样本量分辨不出"下沿"和"轻微退化"。
  它是分类字段，不进向量也不进 FTS，所以对检索无影响；要判定得单独扩样。

## 2. 生产形态下的记录侧可靠性（新读数）

| 项 | 值 |
| --- | --- |
| 英文派生值 ready / pending / failed | **30 / 0 / 0**，三轮全部相同（90/90 turn） |
| `semantic-en-v1` 向量数 == ready 数 | 30 == 30，三轮 |
| 护栏拒绝的派生值 | 0 |

这个数字必须与阶段 1b 报告 §5 里的 **11/20 首轮成功率**并列读，因为两者测的不是同一件事：

- **11/20** 是 `probe-acp-translate.ts` 的**独立翻译调用**——每条 query 一次全新 ACP session，
  只做翻译。失败集中在 `initialize` 超时和"已经是英文的 query 让中→英 prompt 不回 JSON"。
- **30/30 ×3** 是**生产形态**——英文值跟着压缩响应一起回来，一次 session 一个 turn，
  模型手里同时有原文与上下文。

结论：**顺带产出比单独调用可靠得多**，这正是 §5.4 第 1 条选择"同一次响应"的收益，
而且它此前只是推断，现在有读数。它同时说明：一旦将来需要**批量重建**派生值（协议升级），
那条路径会退化到独立调用的可靠性区间，必须自带重试与失败队列。

## 3. 未通过项归因：heldout R-precision

| | run1 | run2 | run3 | 均值 | sd | raw 对照 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| heldout R-precision | 33.3% | 50.0% | 33.3% | 38.9% | 0.096 | **33.3%** |
| heldout hit@5 | 72.2% | 72.2% | 72.2% | 72.2% | 0.000 | 33.3% |

三条事实，合起来就是归因：

**(1) 与协议无关。** raw 对照（同一份 prompt、同样的记录侧派生值、只有 query 侧不给英文形式）
读出**同一个 33.3%**。协议改动不可能既是原因又在对照里同样发生。

**(2) 成因是 RRF 的精确平局 + 按时间打破。** 逐条核对，每轮有 4–6 条 heldout 落在同一个
形状上：期望记录 `ftsRank = 0`（一个字面词都没对上）、`semRank = 1`（语义排第一），而同页
唯一的关键词命中是 `ftsRank = 1`。两者的 RRF 得分**完全相等**：

```
仅语义命中，语义第 1：  1/(60+1) = 0.016393
仅关键词命中，FTS 第 1：1/(60+1) = 0.016393   ← 完全相同
```

平局于是落到 tie-break，而 tie-break 的第一顺位是 `turn_stopped_at` 更新者优先。
结果：**一条语义上完美命中的记录，被一条只是词面撞上的、更新的记录压在下面。**
逐轮命中这个形状的 query：run1 `q29 q32 q36 q39`、run2 `q28 q32 q38 q39`、run3 加到 6 条。

R-precision 在 `|expect| = 1` 时退化成"是否排第 1"，所以这 4–6 条各扣 5.6pp——
33.3% 与 50.0% 之间的全部差距就是这个形状出现了 6 次还是 4 次。

**(3) 阈值本身在 ACP 模式下分辨力不足。** `HELDOUT_R_PRECISION_FLOOR = 0.35` 是在 **gold**
模式下按实测 38.9% 向下留一档定的；gold 模式语料由标注逐字搬运、不波动，所以那里它是个
合理的不回退锁。ACP 模式每轮重新生成正文，实测 sd 0.096（单条 query 5.6pp），阈值离均值
只有 0.6pp —— 它在这个模式下是抛硬币，不是门槛。这正是方案 §9 纪律 3 自查的第一条。

**处置（按纪律，不做的事也写下来）**：

- **不调阈值。** 看到结果再回填等于没有门槛。
- **不在本阶段改融合层。** §5.1 明确写了阶段 1 不动 RRF / 词汇锚点 / 候选池 / 时间窗，
  否则下一阶段的读数就没法归因。
- **登记为阶段 2 的输入**，见 §5。阶段 2 本来就拥有 floor、限额与拆门的决策权，
  这条平局规则和它们在同一层。

## 4. ACP 模式下的检索读数（**不是**单变量对比，不可当协议收益引用）

| | semantic-en（3 轮均值） | raw 对照 |
| --- | ---: | ---: |
| tuned hit@5 | 100.0% | 100.0% |
| tuned MRR | 0.951 | 0.759 |
| tuned R-precision | 90.7% | 61.1% |
| heldout hit@5 | 72.2% | 33.3% |
| heldout MRR | 0.540 | 0.351 |
| expected-empty 平均 / 最坏 | 0.00 / 0 | 0.00 / 0 |
| semantic-only 返回总数 | 80.3 | 130 |
| 跨 workspace 泄漏 | 0 | 0 |

**为什么这张表不能用来宣称协议收益**：ACP 每轮都重新生成 Observation 正文，所以两个 arm
之间同时变了两件事——协议**和**语料措辞。语料措辞直接决定 FTS 命中，而 FTS 命中决定那道
锚点门放不放行。要单变量地证明协议收益，只能看 gold 模式（语料由标注逐字搬运、两个 arm
完全同一份语料），也就是阶段 1b 主报告 §2 的那张表。

这张表的正当用途只有两个：确认 ACP 模式下没有出现 gold 模式看不到的退化（expected-empty
仍 0、泄漏仍 0、tuned 连续性锁仍满分），以及提供 `semanticOnlyTotal 130 → 80` 的第二个
独立观察。
