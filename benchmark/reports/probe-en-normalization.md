# 英文归一化检索方案：可行性实验

> 日期：2026-07-30
> 方案：`plan/V3/retrieval-optimization-plan-2026-07-29.md`
> 前置：阶段 0 已完成、阶段 1a 已完成（`phase1a-encoder-selection.md`，选定 e5-small）
> 状态：**阶段 1b 尚未实施。** 本实验是在 1b 动手前评估一个替代路线，产品代码一行未改。

## 要回答的问题

阶段 1a 选定 `multilingual-e5-small`，代价是包体积 22.6 → 129.1 MB、RSS 178 → 753 MB/进程，
并因此把「向量计算集中到 Worker」从备选升级为 1b 必做项。

替代路线：**不换模型，把检索的两侧都归一到英文。** 入库时给 Observation 加一列英文译文并
对它向量化，检索时用英文 query。依据是 1a 跨语言表里那个反直觉的读数——现有
`all-MiniLM-L6-v2` 在 **en→en 上是四个候选中最高的 0.972**，比 e5 自己最好的一格（0.963）
还高。它不是坏模型，是被喂了读不懂的语言。

1a 只测了三格，缺左下角。本实验补齐四格，再回答三个它引出的问题。

## 方法

| 探针 | 新增/改动 | 回答什么 |
| --- | --- | --- |
| `probe-semantic-rank.ts --lang=zh2en` | 新增语言模式 | 缺的第四格：只译记录、query 不动 |
| `probe-acp-translate.ts` | 新增 | 用**生产 ACP 运行时**独立译出两侧，产出真实译文而非手写镜像 |
| `probe-semantic-rank.ts --en-mirror=` | 新增覆盖入口 | 译者来源的 2×2 分解 |
| `probe-translation-drift.ts` | 新增 | **有效性检查**：两份译文之间到底差多少 |
| `probe-mixed-space.ts` | 新增 | 迁移窗口：中文向量与英文向量能否同表排序 |

编码器一律是生产基线 `all-MiniLM-L6-v2` / q8 / 384d。样本一律是 18 条 `tuned` 校准集，
**`heldout` 全程未跑**（英文镜像按设计不覆盖它）。

## 结果一：四格补齐，只译记录是负收益

| | 记录 zh | 记录 en |
| --- | --- | --- |
| **query zh** | 0.529（现状） | **0.437** ← 本次补测 |
| **query en** | 0.704 | 0.972 |

按主效应读：

| 改动 | ΔMRR |
| --- | --- |
| 只修 query 侧（`zh→zh` → `en→zh`） | **+0.175** |
| 只修记录侧（`zh→zh` → `zh→en`） | **−0.092** |
| 两侧都修 | **+0.443** |

**只译记录比什么都不做更差**，交互项极强——两侧必须匹配。

机制证据在最近邻占用统计里：`zh→en` 下 **t24 是 18 条 query 中 8 条的最近邻**（44%），
而 `zh→zh` 基线里占用最高的 t26 只有 4 条（22%）。中文 query 向量本身在退化区域
（词表 30522 个 token 里只有 244 个纯 CJK），记录换成干净英文之后，连"两侧共享同一种
扭曲"这点残余序信息也没了，query 就只是落到离退化区中心最近的那条记录上。

**结论：query 侧翻译是必需项，不是可选项。** 工程面积最小的那一版（只在 embed 侧加一列、
不动 MCP 入参、不动 agent prompt）被否掉了。

## 结果二：译者独立性不影响排名

0.972 是**同一个译者同时译两侧**得到的，术语一致性被构造消掉了。生产里是两次互不参照的
翻译事件。用生产 ACP 运行时（`kiro-mem-compressor`，`tools: []`）各译一次：records 26 条、
queries 18 条，两次分开的进程调用，prompt 里互不含对侧文本，逐条独立（`ACPPool.run()`
每个 prompt 新建 session，与生产每 turn 一个 session 一致）。44/44 全部成功。

| 组合 | 记录译文 | query 译文 | MRR | median | p90 | Top-5 |
| --- | --- | --- | --- | --- | --- | --- |
| A | 手写 | 手写 | 0.972 | 1 | 1 | 18/18 |
| B | **ACP** | **ACP** | **0.972** | 1 | 1 | 18/18 |
| C | 手写 | ACP | 0.972 | 1 | 1 | 18/18 |
| D | ACP | 手写 | 0.972 | 1 | 1 | 18/18 |

**逐条名次四格完全一致**（17 条第 1 位 + q02 第 2 位，diff 为空）。

### 有效性检查：这个实验里存在可检测的差异吗

四格一位不差，有两种相反解释：编码器吸收了漂移，或者两份译文本来就一样。不区分就引用，
就是 §9 纪律 4 说的中途换层。所以先量漂移本身（判读口径在跑之前写下，见探针头注释）：

| 侧 | n | cosine 中位数 | cosine min | **词面 Jaccard 中位数** |
| --- | --- | --- | --- | --- |
| 记录 | 26 | 0.966 | 0.913 | **0.588** |
| query | 18 | 0.938 | **0.749** | **0.620** |

词面重叠只有 ~0.6，漂移是真实的。最极端的 q09（cosine 0.749）：

```
手写: how is local token auth made invisible to the user
ACP : How does the local token authentication achieve a seamless experience for the user?
```

这一条仍然排第 1 位。所以落 (a)：**这套语料上，MiniLM 的英文空间把译者漂移完全吸收了。**

### 但要如实说明它的举证边界

- 英文任务在这 26 条池子上**接近天花板**（17/18 第 1 位）。向下还有空间（名次可以掉到
  2/3/4），实测没掉；但真实库是这个规模的百倍量级、话题密度也高得多，所以本结论是
  "这个量级的漂移不是灾难性的"，**不是**"漂移在任何规模下都无关"。
- 样本是校准集，且镜像是校准集派生物。`heldout` 没有英文镜像，所以**没有泛化证据**。
- 两个译者是同代同类模型在做忠实翻译。更强的扰动（跨模型代际、或 agent 改写而非翻译）
  未测。

## 结果三：中文向量与英文向量不能同表排序

上线后迁移窗口内语料必然是混的（已重算的是英文向量、没轮到的是中文向量、
`quality=fallback` 的可能永远没译文）。而 `hybridSearchObservations` 把所有语义候选放进
**一张** cosine 排序表再统一编号喂给 RRF，所以两类向量必须同标度可比。

英文 query 下的标度实测（n=18 × 26）：

| 记录语言 | 正例 cosine 中位数 | 噪声 p50 | 噪声 p95 | 噪声 max |
| --- | --- | --- | --- | --- |
| 中文（未翻译） | **0.273** | 0.083 | 0.270 | 0.479 |
| 英文（已翻译） | **0.480** | 0.095 | **0.281** | 0.509 |

**原先担心的"中文侧整体偏高"不成立**——两侧噪声地板几乎相同（p50 0.083 vs 0.095、
p95 0.270 vs 0.281）。§1.1 那个 0.417 的中文地板是 **中文 query × 中文记录** 的读数，
换成英文 query 之后不出现。

真正的问题在信号侧：**未翻译记录的正例中位数 0.273 ≈ 已翻译记录的噪声 p95 0.281**，
两个分布正好压在一起。两个最坏情形分开算（取平均会互相抵消）：

| 配置 | 期望记录 | 其余记录 | MRR | Top-5 |
| --- | --- | --- | --- | --- |
| X | 已翻译 | 中文 | **0.972** | 18/18 |
| Y | **未翻译** | 英文 | **0.613** | 15/18 |

对照：全英文 0.972、全中文记录 + 英文 query 0.704。

配置 Y **比两个端点都差**，且没有任何报错。所以一条未翻译的记录混进已翻译的语料里，会被
**标度之外的信号差**系统性压下去（q18 掉到第 16 位、q17 第 11 位、q13 第 8 位）。

### 但现有机制已经把这个坑挡住了

`getObservationEmbeddingsByIds(ids, { model, dimensions })` **按模型标识过滤读取**，而
`findOrphans` 把模型名对不上的行判为待重建。所以只要把语言折进向量空间标识
（如 `all-MiniLM-L6-v2+en`），**混合 cosine 列表在生产里根本不会出现**：未翻译的记录在
新标识下不存在，语义腿看不到它，退化成关键词可达——那是已有的、文档化的降级路径。

配置 Y 因此不是生产场景，而是一条**反向证据**：它证明为什么绝不能把两类向量放进同一张表。

代价随之明确：**任何拿不到译文的记录都是语义不可达的**（不是"被压低"，是"不在列表里"）。
所以译文覆盖率必须接近 100%，`quality=fallback` 的记录也必须有译文。

### 一个可选的更优解

RRF 只消费**名次**、不消费分数，所以两个向量空间从来不需要同标度——只需要两张独立的
名次表。把语义腿拆成"英文向量腿 + 中文向量腿"两条，各自排名后一起融合，迁移窗口与
fallback 空洞都会变成良性。注意它会改动本方案 §6.2 之前的 RRF 算术前提（记录最多可带
三项而不是两项）。本实验未测，仅登记。

## 与 e5-small 的对照

| | 英文归一化 + MiniLM | e5-small（1a 选定） |
| --- | --- | --- |
| 校准集 MRR（真实独立译文） | **0.972** | 0.907 |
| 包体积（运行文件） | **22.6 MB** | 129.1 MB |
| RSS / 进程 | **178 MB** | 753 MB |
| 冷启动 | **98ms** | 462ms |
| 「向量计算集中到 Worker」 | 退回备选 | 1b 必做 |
| 跨语言弱格 | 不存在（两侧都归一） | cross 0.886 |
| 迁移 | 每条历史记录一次 ACP 调用 | 零 LLM 调用，35 秒重算 |
| 写路径经常性成本 | 每条 Observation 一次 ACP 翻译 | 无 |
| 新增运动部件 | 译文列 + MCP 入参 + agent 约定 + 空间标识 + 覆盖率指标 | 一个常量 + 前缀拆函数 |
| 证据等级 | 校准集（无 heldout） | 校准集 + heldout 0.755 |

## 仍未测的事项

| 项 | 状态 |
| --- | --- |
| heldout 上的英文读数 | **缺。** 要拿到必须译 heldout query。协议：**先在 `tuned` 上做完选择并落盘，再读一次 heldout**，否则这次选择就把它烧掉了（§9 纪律 5） |
| 真实库规模（百倍语料）下漂移是否仍被吸收 | **缺。** 26 条池子上英文任务接近天花板。阶段 3b 的 2k fixture 可以覆盖 |
| 写路径成本（延迟 / 失败率 / fallback 率变化） | **缺。** 翻译放 `embed_observation` job 还是压缩器，成本完全不同 |
| agent 发英文 query 的实际合规率 | 离线测不出。但**可确定性检测**（query 串含 CJK 即未合规），可退回中文嵌入并计指标 |
| 拆语义腿为两条（英文 + 中文）的效果 | **缺**，仅登记 |
| 阶段 2 拆门后英文空间的 floor 工作点 | **缺。** 无关英文句对 cosine ≈ −0.048（中文是 0.417 地板），预期比 e5 的 0.855–0.870 窄带宽松得多，但未扫 |

## 结论

1. **只译记录的廉价版被否掉**（0.437 < 0.529）。query 侧翻译是必需项。
2. **译者独立性在这套语料上不影响排名**（四格 0.972 逐条一致，而漂移实测 Jaccard ~0.6、
   cosine 最低 0.749）。这是本实验最有价值的一条：它拆掉了此前对该方案唯一的定性反对。
3. **两类向量不能同表排序**，但按模型标识版本化后混合列表不会出现；代价是无译文的记录
   语义不可达，所以覆盖率必须接近 100%。
4. 在**校准集**这一级，英文归一化以 1/5.7 的包体积、1/4.2 的进程内存拿到高于 e5 的读数。
   它现在是一个有实测支撑的候选，不再只是构想。
5. 但它仍缺 heldout、缺规模证据、缺写路径成本，而 e5 三项都有。**下一步不是二选一，而是
   补齐这三项里最便宜的两项**：译 heldout query（18 次 ACP 调用，需先落选择结论）与写路径
   成本实测。
