## 0. 三十秒版本

**裁定的问题：误召回的危害应该按"假线索出现了几条"计，还是按"假线索挤掉了几次真答案"计。**

**裁定结果：按后者（Q1 = b），容量作为辅门单独约束（Q2 = b）。**

原先的四道门按前者写。按前者，P3 的 12 个 arm 全败，而且新集测出**假线索最高分 0.604 反超
真答案最高分 0.602**——意味着这个维度上不存在能通过的取值，不是"这次没调好"。

按后者，主门变成"非 acceptable 结果不得排在真答案之前"，现状 35 次，目标 0 次。
这是个排序问题。**但裁定同时否掉了两个过度推论：**

- "没有真答案就不存在危害"**不成立**。错误的 compact card 会占用 agent 的上下文与注意力，
  这个代价由 G2 单独约束，不被判为零。
- 原始分数 AUC **0.841** 只证明 **query 级** top-1 有区分信号，**不证明候选级排序能把 G1 归零**。
  下一步是候选级排序**探针**，不是直接实施。

**若维持旧门，准确表述是"在当前架构和当前证据下不得默认开启"，不是"永久 opt-in"**——
新增证据或架构改变后可重审。且它**不停止 FTS 安全工作**（FTS 假阳性独立存在），
只停止继续围绕现有余弦 floor 做语义选参。

## 3. 为什么现在提：两个已实测的事实

### 3.1 F1/N2 这个方向不存在可通过的取值

零 FTS 的 foreign-domain 负例（页面 100% 由语义腿构成）与正例的分数分布**完全重叠**
（`p3-completion.md` §4.2）：

| 分布 | min | p50 | max |
| --- | ---: | ---: | ---: |
| foreign-domain 零 FTS（17 条）最高假线索分 | 0.206 | 0.356 | **0.604** |
| 正例 query → 自己的 `primary_gold` | 0.086 | 0.391 | **0.602** |

两侧代价曲线：

| floor | 失去语义召回资格的正例 | 仍非零的 foreign 零 FTS |
| ---: | ---: | ---: |
| 0.325 | 19/61 | 9/17 |
| 0.400 | 33/61 | 7/17 |
| 0.500 | 50/61 | 1/17 |
| > 0.604 | **61/61** | 0/17 |

（"失去语义召回资格"= 该 query 与自己 `primary_gold` 的余弦 ≤ floor，语义腿再也捞不到它；
FTS 腿仍可能找回，整页读数看 primary hit@5。）

换一种归一化也不行：P4.0 实测 z(top1) 的 AUC **0.735**，低于原始分数的 **0.841**；
保住全部正例的 z 阈值会放进 **29/30** 条负例，绝对阈值只放进 19/30。机制是负例的语料背景
更低（μ_q 中位 0.095 vs 正例 0.129），归一化系统性地奖励"什么都不相关"的查询。

**所以 F1/N2 不是"这次参数没调好"，是这个维度上没有可用取值。**

### 3.2 位移是可测的、非零的、且在同一份数据上已经量过

N3 = **35 次**，涉及 13 条 relevance query。逐条例子（`p3-completion.md` §4.3，`sr-r51`）：

```text
cap=1  … 4:c39(semantic .413)  5:c22(fts)                                ← gold 在第 5，命中
cap=2  … 4:c39(semantic .413)  5:filler:7437(semantic .408)  6:c22(fts)  ← gold 掉到第 6
```

第 2 个语义配额被一条 filler 假线索占掉，把一条**已被关键词验证**的真答案压出 Top-5。

**这是有明确受害者的危害；F1/N2 量的那种"出现"，在异域查询上没有受害者可指。**

## 4. 提案：把危害口径从"出现"改为"位移"

用于**下一轮尚未冻结的判据**，不追溯任何已完成轮次。

| 新门 | 覆盖 | 要求 | 现状读数 | 取代 |
| --- | --- | --- | --- | --- |
| **G1 排序污染门**（主门） | 61 条 relevance | 非 acceptable 结果排在任一 `primary_gold` 之前 **= 0 次** | **35 次** | 提升 N3 为主门 |
| **G2 容量门** | 没有 `acceptable_gold` 的 query | **整页跨来源** `distinctContent` **≤ 2**，**逐条判定** | 见 §6 | 取代 F1 与 N2 |
| **G3 标记门** | 全部 cohort | 返回项必须携带正确 `match_source`；semantic-only 必须受 cap 约束 | 12 arm × 131 query **全部满足**（S4） | 取代 N1（**删除**"必须全为 `semantic`"） |
| **G4 非回退线** | 61 条 relevance，**四档分层** | 分层 primary hit@5 / MRR **逐档不得回退** | 见 §4.1 | 新增，**与 G1 同等地位** |

四点说明：

**G1 是把 N3 提升为主门，不是 G1 本身收紧。** 公式与阈值与 N3 完全一致，没有任何改动；
变的只是权重——从"四项失败之一"变成"必须归零的那一项"。

**`35 次` 的准确含义是"排在 `primary_gold` 前的非 acceptable 结果数"**，不是 35 个经过
反事实证明的实际位移。`sr-r51`（§3.2）是实际 Top-5 位移的清晰例子，但不能把全部 35 次
都描述成同类事件。

**G2 用 `distinctContent` 口径**，与 P2 判据 r3 的 F1/N2 一致，这样两套读数可以逐层对齐。
逐条判定，不用平均值——不给平均值稀释的空间。

**G3 删掉 N1 的"返回项必须全部为 `semantic`"。** 理由不是它难，是**来源不是相关性标签**：
那 22 条词面锚点 query 的定义就是实测会命中 FTS（S3 复核：`ftsCount` 1…50），所以这道门
在那一侧结构性不可通过。P3 验收裁定已确认它对那一侧没有意义，且"即使完全拿掉 N1，
6 个候选仍同时败在 F1、N2、N3"。

**必须准确表述 G3 的性质**：现有**运行时护栏不变**（`match_source` 正确性、semantic-only cap
都保留，S4 实测 131/131 满足），但**验收门删除了 N1，因此整体门集确实发生了放宽**。
不能把 G3 描述成"不放宽"。

### 4.1 G4 存在的理由：G1 有一个可被利用的退化解

N3 的实现在 `primary_gold` 不在页面时**记 0**：

```ts
// benchmark/run-safety-round-grid.ts:408-411
const nonAcceptableBeforePrimary = pIdx < 0
  ? 0
  : results.slice(0, pIdx).filter((r) => !acceptableObs.has(r.id)).length;
```

因此**把所有结果连同 gold 一起压掉，G1 反而会通过**。不加 G4，G1 单独不构成完整发布门。

G4 的分层沿用 P2 冻结的四档（n = 6 / 9 / 18 / 28），基线读数（floor 0.197…0.300 恒定）：

| 档 | n | 基线 primary hit@5 |
| --- | ---: | ---: |
| `<0.200` | 6 | 0.167 |
| `0.200-0.310` | 9 | 0.556 |
| `0.310-0.400` | 18 | 0.500 |
| `>=0.400` | 28 | 0.929 |

这条线在 P3 已经证明不是空转的过滤器：floor 0.325 让中间两档回退到 0.444 / 0.444，
即使 N1/N2 只覆盖零 FTS 侧、门因此通过，选择规则也会淘汰那个 arm（`p3-completion.md` §4.4）。

两道不过的门分别指向两块**已经登记过归属的、彼此独立的**工作：

- **G1 → 排序污染问题。** 现在的代码丢掉了分数大小：融合只用名次

**关于 AUC 0.841 的边界，必须写清楚（裁定要求第 5 项）：**

P4.0 测到的 `0.841` 是 **query 级 top-1 原始分数**的区分度——它只证明"这个信号存在"，
**不证明候选级排序能把 G1 归零**。两者不是同一件事：前者问"这条 query 整体上像不像有答案"，
后者问"页面内这条候选该排在那条前面吗"。

**并且它与 `0.604 / 0.602` 不是同一份数据集**：`0.841 / 0.735` 来自 P4.0 探针，跑在

`0.604 / 0.602` 来自 P3，跑在 40 条记录 / 131 条 query 的校准集上。
**两份都已消耗**，不得在任何一份上选阈值。

**因此下一步不是直接实施"分数进排序"，而是先在新数据上做候选级排序探针。**
探针结论为"信号在候选级也存在"之后才立项实施；结论为不存在则如实记录并另找方向。
这与 P4.0 同一条纪律：探针不产出可采用的阈值，也不预定实施方案。

**这正是本提案要换取的东西：** 现状是"四门全败、无方向"；重划之后是"两道门、两块边界清楚
且**必须分别取证、分别归因**的工作"。它不降低要通过的难度，它让失败可归因。

同时必须登记一项 G2 无法覆盖的代价：低分正例 `<0.200` 那 6 条，在全部 12 个 arm 上
hit@5 只有 0.167（cap=2）/ 0.333（cap=1）。**这一档在任何候选 floor 下都基本被砍掉**，
换门不改变这件事。

## 7. 三条反驳与回应

### 7.1 "假线索本身就有代价，没挤掉不等于没代价"

**这条反驳成立，我方不辩解，并且原稿在这里写错了一个事实。**

原稿写"注入索引卡在 8KB"作为页面代价的依据，这是错的。`context.maxOutputBytes = 8192`
只作用于 **bootstrap index**（`src/config.ts:62` → `src/bootstrap-context.ts:43`），
**MCP search 页不受它约束**，search 路径完全不引用这个值（已本地核实）。

准确的说法是：**错误的 compact card 会额外占用 agent 的上下文与注意力。** 这个代价不需要
"挤掉某条真答案"就存在，因此"没有真答案就不存在危害"这个论点**不成立**——裁定已明确否掉它。

页面容量的事实仍然值得登记，只是它不来自 8KB：零关键词的 query 整页只有 2 格
（`min(cap, limit)`，实测 56 条主 query 的页面长度只有 0 / 1 / 2 三种），而 30 条负例里
**28 条把 2 格填满**。所以 agent 拿到的不是"10 条里挑一条有用的"，是"2 条都不对"。

**回应：这正是 G2 存在的理由，也是它必须逐条判定、不能用平均值的理由。** G2 判的是
"一条没有 `acceptable_gold` 的查询最多能消耗多少页面容量"。
如果认为 2 条仍然太多，请给一个数——但它必须 ≥1 才有意义，因为 `cap ≤ 1` 会让
"平均 ≤1"成为算术恒真（裁定 §3 已点明，P3 已按此把 6 个 arm 列为诊断臂）。

**并登记 Q4 的约束**：`2` 早于 P3、由 Phase 2B 预登记选择产生，但**它不是独立安全证据**；
下一轮**不得依据同一数据把 2 调高**。

### 7.2 "AI 可能真的照错线索走"

**这条反驳成立，而且我方没有数据。**

`match_source: "semantic"` 标记能减轻多少，**没有测过**。README 写的"verify before acting"
是产品契约，不是实测结论。本提案的整个立论建立在"标记 + 未核实语义"是一个可接受的产品形态上，
而这一点目前是假设。

**回应：只有两条诚实的路，请裁定选哪条。**
（a）承认它是假设，据此接受本提案，并在限制表里如实写"标记的效果未经测量"；
（b）认为这个假设必须先被验证，那就先做那件事——但请明确它是一个**新的取证轮次**，
不是本提案的附加条件，因为它需要的是 agent 行为数据，不是检索读数。

### 7.3 "无解不等于门错了。功能过不了门就别发"

**这条反驳完全成立。**

**回应：我方接受这个结论，但请把它明确写出来。** 因为它的实际含义是：语义发现
**在当前架构和当前证据下不得默认开启**，那 26 条零关键词 query 的 hit@5
`0% → 80.77%`（21/26 进 Top-5、0 退化、MRR 0 → 0.750）作为**默认**能力被放弃。

**表述上有两处必须收窄**（裁定要求第 3 项）：

- 不用"**永久** opt-in"。正确表述是"在当前架构和当前证据下不得默认开启"，
  **未来新增证据或架构改变后可以重审**。
- 这个裁定**不意味着停止 FTS 安全工作**。**FTS 假阳性独立存在**——`sr-a01` 在 floor 0.325 上
  仍返回 10 行纯 `fts`，那与语义发现开不开没有关系。可以停止的只有一件事：
  **继续围绕现有余弦 floor 做语义选参**。不是全部安全研究。

**这是个产品决策，应当被明确作出，而不是通过一道无解的门默认发生。**
