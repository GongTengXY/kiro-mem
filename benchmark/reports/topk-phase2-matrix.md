## 1. 选择结果

`benchmark/select-topk.ts`（确定性脚本，禁止手工抄表）按预登记门槛判定：

```json
{ "semanticCandidatePool": "Infinity", "semanticTopK": 1000 }
```

聚合口径（裁定 B1）：**每次复现都需达标**。不接受中位数，不接受"最小值 + 报告分布"。

`semanticTopK = Infinity` 被**排除在候选之外**，理由是结构性而非读数：它让保留集随语料规模
增长（50,000 档实测均 4,618 / 最坏 14,830 条），不满足判据 §1 承诺的 `O(块大小 + K)`。
即使它的 RSS 落在预算内，也不是本轮要交付的形态。

## 2. 各 K 的门槛判定（含全部失败 arm）

| K | 可行 | 失败项 | 失败读数 |
| ---: | :--: | --- | --- |
| 200 | ❌ | 3 | `S8/T4 名次表仍含 gold`：**3 条 query 触达差异**；`S2 p95` 181.54 / 192.41 / **372.04**ms；`S3 p99` 293.79 / 400.48 / **702.39**ms |
| **1000** | ✅ | 0 | — |
| 5000 | ❌ | 2 | `S2 p95` 250.01 / 257.19 / **535.59**ms；`S3 p99` 328.15 / **538.33** / **1376**ms |
| 20000 | ❌ | 2 | `S2 p95` **270.54 / 332.70 / 348.54**ms（首个已越 300ms）；`S3 p99` 410.01 / 448.83 / **524.03**ms |

K=200 的失败值得单独说明：它在**延迟之外**还有一条确定性失败——3 条 query 的 gold 从名次表
里消失。这不是噪声，而是 K 太小导致 gold 落到保留集之外，`semanticRank` 因此不存在。
它也说明为什么 2,000 条装置的一致性不足以选 K：那份装置上 K=200 的返回页**逐位相同**
（见 §4），问题只在真正会截断的 50,000 档暴露。

## 4. 结果一致性（S1 / S8）

### 4.1 2,000 条装置（276 条 query，对照流式不截断参考）

| K | 有序 `resultIds` 差异 |
| ---: | ---: |
| 200 | **0** / 276 |
| 1000 | **0** / 276 |
| 5000 | **0** / 276 |
| 20000 | **0** / 276 |

四个 K 在这份装置上**全部逐位一致**。原因写清楚：2,000 条装置的过 floor 候选 ≤ ~600，
K ≥ 1000 压根不截断；K=200 虽然截断，但被丢掉的名次都在几百位之后，进不了 10 条的页面。
**因此这份装置无法区分 K**，这正是判据 §6.2 要求在 50,000 档做真截断比较的原因。

### 4.2 50,000 档（真截断）

`topk-selection.json` 记录：K=200/1000/5000/20000 的有序 `resultIds` 与 full-scoring 参考
**差异 0/20**，`match_source` 差异 0。K=200 在这里保留 4,618 条过 floor 候选中的 163 条，
返回页仍然相同——预登记的先验（语义名次到几千位对 RRF 贡献 `1/(60+n)`，配上 cap=2 进不了页面）
成立。K=200 的失败不在页面，而在 `semanticRank` 的可观测性（3 条 query 丢 gold 名次）与延迟。

## 5. 一处必须登记的仪表变更（不影响任何门槛）

同一个 K 的不同复现里，"过 floor 条数"出现两组值：

| arm | 首轮文件 | r2 / r3 |
| --- | ---: | ---: |
| K=200 | 均 **163** / 最坏 231 | 均 4,618 / 最坏 14,830 |
| K=1000 | 均 **760** / 最坏 1,011 | 均 4,618 / 最坏 14,830 |
| K=5000 | 均 **2,725** / 最坏 5,000 | 均 4,618 / 最坏 14,830 |
| K=20000、不截断 | 均 4,618 / 最坏 14,830 | 同 |

原因：首轮用 `semanticRank.size` 统计，那是**保留集**大小，会随 K 一起缩水；r2/r3 改用
`aboveFloorCount`，才是语料性质。K=20000 与不截断两档两者恰好相等（保留集 ≥ 过 floor 数），
所以看不出差别。

这个字段是**诊断读数，不参与任何门槛**（S1–S8 用的是有序 `resultIds`、latency、RSS、样本数、
degrade）。登记它只是为了让同一个 K 出现两个值这件事有解释，不是掩盖。真实的语料性质是
**均 4,618 / 最坏 14,830 条过 floor**。
