# 误召回门形状裁定：采用"位移为主、容量为辅"

> 日期：2026-08-12
>
> 裁定方：Codex
>
> 对象：`benchmark/reports/gate-shape-ruling-request.md`（r1）
>
> 结论：**Q1 = b，Q2 = b。** 采用位移为主、容量为辅的口径，但提案有**七处必须修改**，
> 且 **G1 不能单独构成完整发布门**。
>
> 本裁定**不改变**任何既有结论：C1 仍为 **1.900**，P6 与 Phase 3C 仍**不通过**，
> P3 仍然**没有安全 arm**。生产策略值不变（floor 0.197 / cap 2）。

---

## 1. 裁定的核心

误召回**不再**以"任何假线索出现即失败"为主门。

但提案 §7.3 里"没有真答案就不存在危害"这个论点**不成立**：假线索对无答案查询造成的
上下文、注意力和误导成本是真实的，由 **G2 单独约束**，而不是被判为零。

---

## 2. 逐项裁定

| 问题 | 裁定 |
| --- | --- |
| **Q1** 危害口径 | **b**。G1 为主门，非 acceptable 结果排在 `primary_gold` 之前必须为 0 |
| **Q2** 异域负例 | **b**。所有没有 `acceptable_gold` 的 query，**整页跨来源** `distinctContent ≤ 2`，**逐条判定，不用平均值** |
| **Q3** 是否永久 opt-in | **否，不接受"永久"表述。** 若维持旧门，只能裁定"**在当前架构和当前证据下不得默认开启**"。未来新增证据或架构改变后可以重审 |
| **Q4** 数字 `2` 是否被污染 | **否**。它早于 P3，由 Phase 2B 预登记选择产生。**但它不是独立安全证据：下一轮不得依据同一数据把 2 调高** |
| **Q5** 删除 N1 | **成立**。来源不是相关性标签。删除"结果必须全部为 `semantic`"，保留 `match_source` 正确性与 semantic-only cap |
| **Q6** 标记效果 | **b**。稳定发布前**必须另做 agent 行为取证**。它**不阻塞** G1–G3 冻结，但构成**默认开启前的发布条件** |
| **Q7** 补限制表 | **要**。必须**连同适用边界一起写**，不能只写 `0.604 > 0.602` |
| **Q8** 提出时机 | **合法**。它不重判 P3，只为下一轮提出前瞻性产品门；**但新轮次必须使用新冻结数据** |

## 3. 对三道新门的裁定：G1 不能单独构成完整发布门

G1–G3 可以作为下一轮安全门，但需要一项补充。

### 3.1 G1 有一个可被利用的退化解

当前 N3 在 `primary_gold` 不在页面时**记 0**。代码出处已核实：

```ts
// benchmark/run-safety-round-grid.ts:408-411
const nonAcceptableBeforePrimary = pIdx < 0
  ? 0
  : results.slice(0, pIdx).filter((r) => !acceptableObs.has(r.id)).length;
```

因此**若把所有结果连同 gold 一起压掉，G1 反而会通过**。

**裁定：下一轮必须继续保留分层 primary hit@5 / MRR 不回退线，作为与 G1 同等地位的
资格过滤器。不能用"清空页面"换取位移归零。**

### 3.2 G1 的名称与读数口径

**建议改名为"排序污染门"。**

`35 次` 的准确含义是"**排在 `primary_gold` 前的非 acceptable 结果数**"，
**不是 35 个经过反事实证明的实际位移**。`sr-r51` 是实际 Top-5 位移的清晰例子，
但**不能把全部 35 次都描述成同类事件**。

## 4. 七处必须修改

| # | 要求 | 性质 |
| --- | --- | --- |
| 1 | **保留** §1 的"这是放宽安全标准"——它不是姿态过低，而是准确披露。但把 G1 称作"**提升为主门**"，不要称"G1 本身收紧"，因为它与 N3 的公式、阈值没有变化 | 表述准确性 |
| 2 | **保留** §11 第 1 条。门形状是在看过 P3 数据后提出的，这条边界必须登记。它不使提案非法，但意味着**旧数据只能支持立项，不能证明新门有效** | 证据强度 |
| 3 | 修改 §7.3 与 Q3：**删除"永久 opt-in"与"立刻停止 F1"的承诺**。FTS 假阳性独立存在，不能因为语义发现改成 opt-in 就自动停止 FTS 安全工作。可以停止的是**继续围绕现有余弦 floor 做语义选参**，不是全部安全研究 | 事实错误 |
| 4 | 修改 §7.1：**8KB 是 bootstrap index 的预算，不是 MCP search 页的硬预算**。应改成"错误 compact cards 会额外占用 agent 上下文与注意力" | 事实错误 |
| 5 | 修改 AUC 论证：**0.841 只证明 query 级 top-1 原始分数有区分信号，不证明候选级排序能把 G1 归零**。下一步应先在新数据上做**候选级排序探针**，不能直接预定"分数进排序"就是实施方案 | 过度外推 |
| 6 | 修改 §9 的 `Q1=b, Q2=b` 路径：**不能写"不建中文 filler、只做排序"**。文档自己预测 G2 在词面锚点侧仍失败，因此 FTS 准入轮次仍需继续。正确路径是：**G1 候选级排序取证与 G2 FTS 准入取证分开进行，分别归因** | 逻辑自相矛盾 |
| 7 | "G3 不放宽"改成更精确的表述：**现有运行时护栏不变，但验收门删除了 N1，因此整体门集确实发生了放宽** | 表述准确性 |

---

## 5. 对 FTS 轮次的直接后果

**当前 FTS 方案的 L1–L4 不应原样冻结。**

顺序：先按本裁定改为 **G1 / G2 / G3 + 正例分层不回退线**，然后才能进入 F1。

---

## 6. 本裁定不授权什么

- 不授权修改 `DEFAULT_RETRIEVAL_POLICY`（floor 保持 0.197 / cap 保持 2）；
- 不授权重判 C1（正式读数永远 1.900）、P6 或 Phase 3C（永远不通过）；
- 不授权在已消耗数据上选参——**新轮次必须使用新冻结数据**（Q8）；
- 不授权依据同一数据把 G2 的 `2` 调高（Q4）；
- 不授权在完成 agent 行为取证之前把语义发现设为**默认开启**（Q6）。
