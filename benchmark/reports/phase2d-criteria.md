> 落盘时间：2026-08-03

## 1. 结构诊断：§9.3 的主判据在合法选参集上不可达

方案 §9.3 规定 2D 的选参只允许使用 Gate A 冻结的 Phase 2 扩展校准集与既有 `tuned`
连续性锁，主判据是「Phase 2 relevance MRR 或 R-precision 至少一项上升」。

实测：**14 个 arm（基线 + `source-confidence` + 12 个 `rrfK × w_sem`）在 Phase 2 校准集的
全部 121 行上逐位零差异。**

| 子集 | 行数 | 14 个 arm 的差异行数 |
| --- | ---: | ---: |
| Phase 2 relevance（全部 `ftsCount=0`） | 72 | **0** |
| empty（既有 5 + Phase 2 49） | 54 | **0** |
| leakage | 1 | 仅 `match_source` 次序，R-precision 两侧均 1 |
| tuned relevance（连续性锁） | 18 | 1（arm 1）/ 6（w_sem>1） |

原因是结构性的，不是样本量问题：Phase 2 校准集由 2A 按 `ftsCount === 0` 一条判据筛出，
**集合里每一条 query 只有语义腿在工作**。而 semantic-only 候选的融合分是

```text
score = w_sem / (rrfK + semRank)
```

它对任何 `w_sem > 0`、`rrfK > 0` 都随 `semRank` 单调递减，所以 semantic-only 之间的相对
次序恒等于 `semRank` 次序，与权重和 K 无关；tie-break 只在分数精确相等时生效，而不同
`semRank` 不会相等。**一个只有单腿命中的集合，在结构上无法测量融合层的任何改动。**

这与方案自己反复登记的错误同类（v2 推论：「拿一个结构上动不了的端到端读数当门槛，等于
把正确的改动判成失败」）。因此 2D 不能沿用 §9.3 的主判据，也不能因为它不动就宣称 2D 无收益。

**连带结论**：`rrfK` 在本语料上是空操作。`k30-wsem1` / `k60-wsem1` / `k90-wsem1` 三个 arm
与基线**逐位零差异**（145/145 行），所以 §9.2 实验二的 `rrfK ∈ {30,60,90}` 这一维在当前
数据上不携带任何信息。这是读数，不是推断。

## 2. 结构诊断：§9.1 登记的 tie-break 触及不到主导平局形状

arm 1（`source-confidence`：`hybrid > semantic-only > fts-only > recency > id`）在 145 行里
只改了 2 行（q10、q20），两行都只是页面第 2、3 位的 `fts` 与 `semantic` 互换，**没有任何
指标变化**。

而 `w_sem > 1` 改了 7 行，其中 3 行是真实名次改善（q03、q04、q14：期望目标 rank 2 → 1）。
这 3 行共享同一形状：

```text
目标        ftsRank=2, semRank=1  →  1/(60+2) + 1/(60+1) = 0.0325223…
压住它的    ftsRank=1, semRank=2  →  1/(60+1) + 1/(60+2) = 0.0325223…   ← 精确相等
```

两者都是 `hybrid`，所以 `source-confidence` 的第一顺位（按 match_source 分档）**对它们完全
失效**，直接落到 recency。也就是说：§9.1 描述的平局（semantic-only rank r 撞 fts-only
rank r）确实存在，但它在本语料上不携带指标；**真正压住期望目标的是同源、腿内名次互换的
hybrid 平局**，而登记的 tie-break 结构上看不见这一类。

## 3. arm 3 的来源与目的（在实现和运行之前写明，§7.2 纪律）

**来源**：上面第 2 节的机制，不是任何指标读数。

**目的**：用最小的改动触及第 2 节的平局形状。方案 §9.3 末句要求「如简单的 tie-break 已
解决主要问题，优先选更小的改动」，而 arm 1 被证明触及不到，arm 2 的 `w_sem>1` 会改变
**非平局**候选的相对分数（q13 的页面成员因此变化，2 条 fts-only 被挤出），超出了 §9.1
登记的缺陷范围。所以需要一个「只在精确平局上生效、但能分辨同源平局」的候选。

**定义**（`tieBreak: 'semantic-rank'`）：仅当融合分精确相等时，

```text
1. 语义名次更好（更小）者优先；没有语义名次的排在任何有语义名次的之后；
2. 再按 turn_stopped_at 更新者优先；
3. 再按 id 更小者优先。
```

为什么第 1 顺位是语义名次而不是词面名次：这是本项目已实测的两腿质量差。
`semantic-en-v1` 的离线语义排名 MRR 是 tuned 0.972 / heldout 0.833（`phase1a` 报告），而
FTS 名次来自 trigram 单元上的 bm25，§1 的病因诊断本身就是「词面命中 ≠ 相关」。在两条腿
给出精确相等证据时优先信更强的排序器，依据是读数而不是偏好。

它与 arm 1 的关系是严格包含：K=60 下跨腿数（hybrid vs 单腿）的精确平局不可能成立
（`1/(K+s)` 取不到 `1/61+1/62`），所以一切可达的平局都是同腿数的——单腿对单腿时
`semantic-rank` 与 `source-confidence` 给出相同结果（有 semRank 者优先），hybrid 对
hybrid 时只有 `semantic-rank` 能分辨。

## 4. 判据（在 arm 3 运行之前写死）

因为第 1 节证明了 §9.3 的主判据不可达，2D 的判据改为下列四条。**tuned 的读数只能用作
D2 的不回退锁与 D3 的影响面度量，不得用来回答「哪个 arm 更好」**——它是连续性锁，检索
实现就是在它上面调出来的。

| # | 判据 | 举证方式 |
| --- | --- | --- |
| **D1** | 候选必须修复 §9.1 登记的缺陷：精确平局不再由 recency 决定，且改动**只**在精确平局上生效 | fixture，不用指标 |
| **D2** | 不回退锁：Phase 2 hit@5 / MRR / R-prec 不回退；Phase 2 empty 均值与最坏不恶化；既有 expected-empty 不恶化；tuned hit@5 / MRR / R-prec 不回退；semantic-only ≤ cap 不变量成立；跨 scope 泄漏 0；p95 < 300ms | benchmark 全表 |
| **D3** | 在同时满足 D1、D2 的候选里，选**对非平局候选影响最小**者。度量：与基线相比页面成员或 `match_source` 组合发生变化的 query 条数 | 逐 query diff |
| **D4** | 若没有候选同时满足 D1 与 D2，2D 结论为**未通过**，登记后进入 3A，不得为了让 2D「有产出」而放宽 D1 或改用 tuned 选参 | — |

# 事后附录（在 arm 3 读数出现**之后**写，上文一字未改）

## A1. 预登记分支不完备，必须披露

§5 的 B1 写的是「arm 3 复现 q03/q04/q14 的名次改善」，B2 写的是「arm 3 语料上零差异」。
实测落在两者之间：arm 3 复现了 **q03 与 q14**，没有复现 **q04**，改动 4 行。**预写的分支集
没有覆盖这个部分命中的情况**，这是判据本身的缺陷，记在这里而不是悄悄重新解释。

补救方式不是重写分支，而是把 D1 从"我判断哪些是平局"改成一个**机械可复跑的读数**，并且这个
读数不依赖任何质量指标：

新增诊断 arm `diag-wsem-epsilon`（`w_sem = 1.000001`）。一个无穷小的语义加权在数学上只能
翻转分数**精确相等**的候选对——任何严格领先都不会被 ε 翻动——所以

```text
「w_sem=1+ε 改变的行」 ≡ 「结果由精确平局决定的行」
```

实测该集合为 **{q03, q10, q14, q20}**，4 条，且 `w_sem=1+ε` 与 arm 3 的**逐 query 结果与
全部指标完全相同**（tuned MRR 0.944 / R-prec 88.9%，改动集 4 行一致）。

由此 D1 被机械化为：候选的改动集必须**正好等于**平局集——漏了说明平局没修完，多了说明它
动了本来没有平局的候选。这不是新判据，是 D1 原文「改动只在精确平局上生效」的可执行形式。

## A2. q04 / q06 / q13 被证明不是平局，因此在 D1 范围之外

`w_sem=1.000001` 与 `w_sem=1.01` 都**不改变** q04 / q06 / q13；只有 `w_sem ≥ 1.1` 才改变
它们。所以压住 q04 的候选在 1:1 权重下是**严格领先**，不是平局。

这把 `w_sem>1` 的收益分成两段，两段的性质不同：

| 来源 | tuned MRR | tuned R-prec | 是否 §9.1 登记的缺陷 |
| --- | ---: | ---: | --- |
| 基线 | 0.889 | 83.3% | — |
| 精确平局（q03、q14） | **0.944** | **88.9%** | 是 |
| 非平局重加权（q04） | 0.972 | 88.9% | **否** |

第二段是「语义腿是否应该比词面腿权重更高」这个质量调参问题。它超出 §9.1 登记的缺陷，而且
**没有合法选参集**：Phase 2 校准集在结构上测不到它（§1），`tuned` 是连续性锁不能用来选参
（D4）。所以本轮不动权重，把它按 §13 登记给后续阶段，需要先有一份两腿都命中的冻结校准集。

## A3. 选参结果

`benchmark/select-phase2d-arm.ts` 只读 `phase2d/grid.json`（全部 arm 均 `--no-heldout`，
脚本另有确认集污染自检）并机械执行 D1–D3，输出唯一可行候选：

```text
tieBreak: 'semantic-rank'   （floor / cap / rrfK / 权重全部保持 2C 冻结值）
```

- `tb-source-confidence`：漏 q03、q14 两条平局（同源 hybrid 平局，按 match_source 分档看不见）→ D1 不通过；
- 全部 `w_sem ≥ 1.1` arm：多动 q04、q06、q13 三条非平局候选 → D1 不通过；
- 全部 `w_sem = 1` arm（含 `rrfK` 30/90）：与基线零差异，四条平局一条没修 → D1 不通过。

D2 在所有 arm 上都成立，所以 D1 是唯一起作用的判据；D3 未被用到（可行集只有一个元素）。

## A4. 平局集改为实测，D1 相应改写

**问题（Gate D P2）**：附录 A1 把 `w_sem = 1+ε` 说成「数学上只能翻转分数精确相等的候选对」。
这句不成立——`1.000001` 是**有限**扰动，一般情况下可以翻转分数只是足够接近的严格有序对，
而生产比较器判的是 float64 `===`。所以 ε 只能是辅助诊断，不能定义平局集。

**整改**：内核 `onFusion` 新增 `ranked`，报出它**自己算出的**融合分与排序；benchmark 按
float64 `===` 分组枚举平局，只把「至少一名成员进了结果页」的组计入（页外深处的平局不影响
任何指标）。逐 query 落 `exactTiePairs` / `exactTieInPage`，聚合落 `exactTie*Queries`。

**实测结果与 ε 的差距很大，说明这次整改不是形式主义**：

| 运行 | ε 推断 | 实测平局进页 |
| --- | ---: | ---: |
| `--phase2 --no-heldout`（145 行） | 4 | **9** |
| heldout 确认集（42 行） | 4 | **11**（其中 heldout 子集 **2** 条：q26、q38） |
| validation 确认集（62 行） | 5 | **18** |

原判据「改动集必须**正好等于**平局集」因此是错的：一条平局 query 上，规则按证据判出的次序
可能恰好与 recency 相同，那样它不进改动集，但平局确实已不由时间戳决定。D1 改为：

| # | 修订后判据 |
| --- | --- |
| **D1a** | 改动集 **⊆** 实测平局集。任何落在平局集之外的改动都说明它不再只是 tie-break |
| **D1b** | 改动集非空——必须真的解决了什么 |
| **D2** | 不回退锁，与上文同 |
| **D3** | 不得与方案登记的 `source-confidence` 结论冲突：凡它决定了的 query，候选必须也决定且给出同一结果（机械部分查改动集超集关系，同解由 fixture 保证） |
| **D4** | 可行集里解决更多平局 query 者优先；再相同按 arm 名字典序，保证确定性 |

原 D3「对非平局候选影响最小」被 **D1a 完全吸收**（可行候选对非平局候选的影响恒为 0），
它不再有区分能力。剩下的区分维度是「解决了多少登记缺陷」，方向与原 D3 相反——**这是判据
方向的实质改动，写在这里而不是藏在结论里**。它对结论没有影响：胜出者的改动集是次优者的
严格超集，两种方向下 D1a 都排除了全部加权 arm。

**加权 arm 的排除理由现在是实测的**：它们改动 q04 与 q13，而这两条**不在**平局集内——
越界改动严格有序的候选，D1a 直接拒。此前这个结论依赖 ε 差集，现在不依赖了。

## A5. `semantic-rank` 原设计不是保守扩展，已改

**问题（Gate D P1-2）**：上文 §3 与源码注释都声称 K=60 下 hybrid 与单腿候选不可能精确平局。
**这是错的**，反例在候选范围内：

```text
1/93 + 1/186 === 1/62      // hybrid(ftsRank=33, semRank=126) 撞单腿 rank=2
```

float64 下精确相等。穷举 `ftsRank ≤ 50`（FTS 内部 limit）× `semRank ≤ 250`（候选池上界），
**共 17 组解**。原设计「语义名次优先」会把这些平局判给 semantic-only，与方案登记的
`source-confidence` 结论相反——一条未经校准的新边界。

**整改**：比较器改为 `source-confidence 分档 → 语义名次 → recency → id`。它在
`source-confidence` 能决定的每一个平局上给出**同一答案**，只在同档内（主要是名次互换的
hybrid 对）多给一个答案，因此是真正的保守扩展。q03 / q14 仍然被解决——它们本来就是同档。

新增两条 fixture：K=60 反例的算术断言（含 17 组解的穷举下界），以及 `rrfK=1` 下的三方
跨腿数平局（`1/4 + 1/4 === 1/2`），断言 `semantic-rank` 与 `source-confidence` 逐条同解、
且首位是 hybrid。后者用 K=1 是因为同一套算术在 K=1 下只需 3 条词面 + 3 条语义候选，而 K=60
的实例需要 126 条语义候选；被检验的性质与 K 无关。

## A6. 网格可复现性（Gate D P1-1）

原驱动的 baseline 不传 `--tie-break`，靠内核默认值。2D 落地默认值之后，按提交文档重跑会把
baseline 变成候选，静默覆盖证据。已整改：每个 arm 从冻结的 2C policy 出发，**生成全部 7 个
字段的参数**（不是「基线参数 + 覆盖参数」——`run.ts` 取第一个匹配的 `--name=`，重复参数会
静默保留基线值），运行后与预期 policy 逐字段断言，报告先写 `.staging`、断言通过才落正式路径。

这条整改当场抓到一个真 bug：第一版仍用「基线 flag + 覆盖 flag」拼接，于是
`--tie-break=recency --tie-break=source-confidence` 让 arm 实际跑的是 recency。断言直接报错
退出，没有产出一份看起来正常的报告。

# 第三次修订（Gate D 第二轮反馈后，2026-08-03 晚；上文一字未改）

Gate D **再次未通过**。排序实现这次没问题，问题在 benchmark 的确定性——而它直接污染了本
阶段的基线。**判据与实验装置到此被改过三次**，三次都是外部复核指出的。

## A7. recency 基线本身不确定（P1-1）

`benchmark/run.ts` 播种时调 `markTurnClosed(turn.id)` 不传时间，`src/db/index.ts` 因此落回
运行时 `new Date()`。于是同一毫秒内关闭的 turn 按 id 排、跨毫秒的按时间戳排——**`recency`
的第一顺位取值随机器快慢变化**。

Codex 实证：同一份代码 hash、数据 hash、同一个 `tieBreak=recency`，正式报告里 v16 是
`hybrid+semantic+fts`，独立复跑两次都是 `hybrid+fts+semantic`。这不是指标噪声，是**正在被
比较的基线行为**在变。

**整改**：播种给每个 turn 显式、唯一、确定性的 `stopped_at`——当天 UTC 零点往前 30 天为
基准，按数据集顺序每 turn 加 1 分钟。任何两个 turn 时间都不同，`recency` 永远在第一顺位
决出结果，不会退到 id（两个顺位混用才是不确定性的来源）。

**中途踩到的坑，值得留档**：第一版用写死的 `2026-01-01`。当天就跑不通——`search` 的默认
时间窗是 90 天且相对墙上时钟计算，所有记录被窗口过滤，`allGatesOk: false`、全部 hit@5 归零。
所以确定性的正确口径是「同一天内逐位可复现，跨天整体平移」：平移均匀，相对次序、间隔和
落在窗口内三件事都不变。写死绝对日期会让基准集在某一天静默失效，比不确定更糟。

**验证**：同一命令连跑 3 次，62 行逐 query **0 差异**，门槛全过，平局进页稳定 18 条。
v16 稳定为 `hybrid+fts+semantic`，与 Codex 两次复跑一致。

## A8. 行为 fingerprint 之前不是完整页面（P1-2）

`QueryRow` 只存期望名次、**去重后的** `matchSources`、返回条数等，没有有序结果 id。两条
无关 hybrid 互换位置时这些字段可能全不变，逐 query diff 因此漏报。

**整改**：`QueryRow` 新增 `resultIds`——返回页的**有序**数据集 id，并进入 fingerprint。
用数据集 id 而不是数据库自增 id：与播种顺序解耦，报告里也读得懂。

**漏报量不小，所有"改动 N 条"的读数都得改**：

| arm | 旧（漏报） | 新（完整页面） |
| --- | ---: | ---: |
| `tb-source-confidence` | 2 | **3** |
| `tb-semantic-rank` | 4 | **5** |
| 全部 `w_sem ≥ 1.1` | 7 | **9** |
| `diag-wsem-epsilon` | 4 | **5** |
| heldout 确认集 | 4 | **5** |
| validation 确认集 | 5 | **8**（新增 v16、v20） |

指标读数没有变——漏报的都是不影响 hit@5 / MRR / R-precision 的次序变化。但 D4 的「解决了
多少平局」和「候选是 `source-confidence` 改动集的超集」这两个论断，此前**无法机械证明**，
现在可以：`{q02,q10,q20} ⊂ {q02,q03,q10,q14,q20}`。

## A9. staging 只保护了 JSON（P2）

Markdown 直接写正式路径，policy 断言失败时会留下「新 MD + 旧 JSON」——一份自相矛盾的证据
比没有证据更糟。已改为两份都先写 `.staging`，断言通过后一起替换。

## A10. 全部证据按 grid → selection → confirmation 顺序重新落盘（P1-4）

旧的 confirmation 早于最终 grid/selection 生成，且缺 v16 的次序变化。修确定性后已按正确
顺序全部重跑，时间戳可核。
