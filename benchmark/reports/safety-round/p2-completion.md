### 0.1 第 4 项牵出的一个机制隐患

原先种子是从**活的**判据 SHA 现算的（`freeze.criteriaSha256.slice(0, 8)`）。第 1、2 项要改判据

报告里记明它的出处仍是判据 r2 的 SHA 前 8 位（即首次洗牌当时的值，在任何洗牌结果可见之前
就已确定）。钉死后复算，**40 条年龄与插入顺序逐条不变**（`s01:432/28` `s02:752/25`
`s03:580/3` …），Spearman 仍是 −0.031 / −0.146。脚本 SHA 现在四处一致（实际文件 / `turns`
的 `meta` / 年龄报告 / 冻结总表，均为 `022230be…`）。

## 4. 两个机制发现（不在原计划内，值得记录）

### 4.1 中文 query 的"零 FTS"在 trigram 分词下几乎不可达

首次验证：40 条 empty 里 **25 条**实际命中、30 条锚点里 **8 条**未命中。机制有两条：

1. 中文口语功能词的三字串（`有没有` / `能不能` / `怎么选` / `返回的` / `的模型`）在几乎任何
   中文提问里都出现，因此必然命中一个 10k 语料；
2. 两字词（`余弦` / `模型` / `维度` / `队列` / `内存` / `副本` / `排名` / `重试`）在 trigram 下
   **永远无法单独命中**——想让锚点真的命中，锚点必须是语料里真实存在的 ≥3 字串。

处置：改写 33 条问法——empty 侧改用书面式（`是否` / `有无` / `可否`）避开功能词三字串，
锚点侧改用 `相似度` / `重试耗尽` / `多个副本` / `持久化` 这类真实存在的长锚点。
**事实一条未改，只改表层问法**——这正是这两个 cohort 的定义所在。
最终 empty 40 条全为 0，锚点 30 条全部命中（`ftsCount` 1…50）。

这一条对 P3 有直接含义：**词面锚点那 30 条确实覆盖到了 FTS / hybrid 绕过配额的暴露面**，
因为它们的锚点是被实测确认会命中的，不是声称会命中的。

### 4.2 低分正例带只有 0.11 宽，命中率约 1/10

落在 `[0.200, 0.310)` 的问法有共同形状：**具体主语 + 二选一式追问，且避开记录自己的名词**。
过于口语化会掉到 `<0.200`，直接用记录术语会升到 `>0.310`。因此四轮共补写 20 条才凑够 9 条。
`<0.200` 那一档有 6 条，它们在任何候选 floor 下都会被砍掉——这是必须被看见的代价，
报告里单独列出，不得为了好看而删除。

## 5. 诚实边界

1. **本语料是"基于真实产物重建的 gold fixture"**，不是真实捕获的对话或生产数据，
   也不得用于 ACP 压缩质量评估（判据 §2.1、§8.1、§8.2）。
2. **标注者与撰写者是同一人**，且已看过前几轮的读数。这比独立第三方标注弱。它强的地方只有一处：
   这些具体问法与这 40 条记录从未参与过任何参数选择。
3. **英文形式的首轮成功率 79.3%**（88/111），失败形状全为"模型回解释而不是 JSON"，
   与阶段 1b 实测一致；定向重试后补齐。冻结的是重试后的固定输入，不是首轮产出。
4. **零 FTS 确认播了 1 份 filler 而不是 5 份**。副本是同一段文本，命中数按份数成倍，
   但零/非零判定与份数无关；结论为零时播 5 份仍为零。全程未建向量、未跑语义腿。
5. **本轮没有放宽项。** r2 曾用 N4 给 near-domain 免掉数量门，已由复审推翻；r3 的 N2 与 C1
   同量级（`distinctContent` 平均 ≤ 1）。**方案 D3 的实测说明这个门很可能过不去**——near-domain
   去重后在 floor 0.197→0.320 之间只从 1.50 降到 1.15。那也是一个结论，而且有信息量：
   它说明 floor × cap 不足以约束 near-domain，需要另开轮次，而不是把门槛改宽。
   C1 的正式读数永远是 1.900，P6 与 Phase 3C 永远是不通过——F1/N1–N3 是新集上的新门，
   与 C1 并列，不覆盖它。
