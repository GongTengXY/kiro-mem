## 1. 这一轮为什么是 r2

r1 的 F1 冻结之后，F2 的 S4 在完整装置上拦下 **9 条零命中词面负例**。按裁定作废重开，
并新增**冻结前数据资格门**——那道门随后查出的问题比 S4 暴露的多得多：

| 门 | r1 数据的实测 | 性质 |
| --- | --- | --- |
| Q1 负例 `ftsCount ≥ 1` | 失败 **9/40** | 与 S4 一致 |
| Q2 锚点索引可达 | 失败 **26/40** | 那 26 条的锚点**不是**它们命中的原因 |
| Q3 保护线 gold 词面可达 | 失败 **12/40** | 其中 10 条的 token 只存在于 `fact_source` |
| Q4 基线非空门 | 失败 **12/40** | 与 Q3 同源：基线不可达即"不得回退"空转 |

两类根因，都是**未测量就断言**：

1. **两字锚点在三字窗下结构性不可达**。`记录` 出现在 10,012 行，但跨过它的三字窗
   （`记录的` / `条记录`）在语料里对不上邻字。这正是 F0-2 登记的机制，而我在写负例时
   违背了本轮自己的发现。
2. **锚点在语料里根本不存在**。`候选池` / `时间窗` 的子串出现次数是 **0 行**，
   而 r1 的 `lexical_anchor_basis` 断言它们出现在某几条记录里。

修复严格按裁定执行：**只改 query token，记录侧一个字节未动**；38 条改动写在补丁表
（`build-fts-round-queries-r2.ts`）里，每条带原值、新值、`token_source`、`measured_df`
与理由；数据文件保留 `query_r1` / `lexical_anchor_r1` / `primary_gold_r1` 供逐条核对。

原 `f1-freeze.json`（14 项输入）、`f2-fixture.json`（S4 拦截证据）、`f2-strata.json`
全部**逐字节保留**，覆盖由 `freeze-util` 硬失败保证而不是靠自觉。

## 4. S7a：K = 200（前置门通过）

阶梯 `[200, 1000, 5000, EXACT]`，判定**只用正确性**：

```text
K=200：16 arm × 120 query = 1920 组比对，与 EXACT 差异 0 组，15.6s
⇒ 取阶梯最小档 K = 200
```

这把 r1 那个未受控的第三变量**结构性消除**了：要么某个有限 K 与精确语义逐条相同，
要么就用精确实现。`EXACT` 的差集恒为 0，所以阶梯不会走空。

**S6 恒等锚点**：基线臂 `r0-d1.00`（两个变量都关闭）与生产 `searchObservationsFts`
**120/120 逐条相同**——`r = 0` 时 `ceil(0 × W) = 0`，准入条件恒真，这不是巧合而是构造。

## 5. 准入机制自身的读数（不是门读数）

| arm | 均返回 | 空返回 | 缩水页 | 丢弃单元 | 豁免命中 |
| --- | ---: | ---: | ---: | ---: | ---: |
| `r0-d1.00`（基线） | 17.78 | 4 | 0 | 0 | 86 |
| `r0.1-*` | 5.23 | 26 | 71 | 0…7 | 86 |
| `r0.2-*` | 1.96 | 57 | 78…79 | 0…7 | 86 |
| `r0.3-*` | 1.37 | 76 | 81…82 | 0…7 | 86 |

三件事值得先记下来，它们会直接决定 F3 的形状：

1. **V1 咬得很紧。** `r = 0.3` 时 120 条 query 里有 76 条零返回。G4 与召回保护线是否
   拦得住这个方向，就是 F3 的主要问题。
2. **V2 在这个装置上近乎惰性。** `d` 从 1.0 到 0.03，被丢弃的单元总数只有 0 / 0 / 1 / 7——
   60,066 行下连最高频功能词的 `df/scope` 也只有 0.0416，低于 0.10 这一档。
   **刻度已冻结，不因这个读数改动**（判据 §2.4 第 2 条）。这意味着 F3 很可能读到
   "V2 的效应在本装置上不可分辨"，那是个有信息量的结论，不是失败。
3. **精确单元豁免恒为 86 条命中。** 它是拉丁 / 路径 / 数字 query 不被覆盖度打死的原因，
   也是判据 §11 预测二要验证的那个代价：混排 query 里的拉丁锚点会让负例一起被豁免。

## 6. 诚实边界

1. **本文不含任何门读数。** G1–G4、召回保护线、性能资格门全部属 F3。
2. **中文 filler 是模板生成的合成语料**，自证的是"分布非退化且未被反向塑造"，
   不是"与真实中文工作区同分布"（r3 §12 第 3 条）。
3. **`f2-fixture-r2.json` 的一致性比较用的是同口径截断值**：预检的 `ftsCount` 是带可达
   上限 2000 的返回列表长度，会在超限时饱和（实测 5 条落在 2502…2899），因此比较
   `min(ftsCount, 2000)`，真实计数另列。门的结论不受影响：Q1 判 ≥1，Q3/Q4 判 gold 是否
   在返回集合里，而全部 gold 的命中位次都远小于 2000。
4. **Q2 的判定形式化在看到首次预检结果之后更正过**（r4 §16.1.1）：原文"单元包含锚点"
   在锚点长于三字时恒假。更正只改可执行性，不改任何门槛数值，且当时无任何 arm 读数。
5. 修复过程中我**第二次**犯了同一个错误：把 `预警` 改成 `缺口预警` 时未测量，实测 0 行；
   工具当场抓住，最终改用实测存在的 `四周预警`（182 行）。这条登记在补丁表里。
6. **撰写者、数据作者与判定者仍是同一人**，缓解方式是四道门与全部自证都是机械计算、
   由脚本硬失败，不依赖人工复核（r4 §18 把 sample gate 的那处漏项也变成了机械门）。
