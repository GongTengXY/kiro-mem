# FTS 安全策略轮次 F0：词面命中机制诊断

> 日期：2026-08-12
>
> 角色：**描述性诊断，不选任何阈值、不裁定任何门。**
>
> 脚本：`benchmark/analyze-fts-anchor-mechanism.ts` → `f0-anchor-mechanism.json`
>
> 数据：P3 **已消耗**的校准集（方案 §4 禁止清单第 1 条只允许描述性测量）。
> 装置与 P3 逐行相同（50,066 行），但**不建向量**——本诊断只跑 FTS 腿，25 秒。

---

## 0. 为什么要先做这个

P3 测到了"floor 0.325 上 `sr-a01` 仍返回满页 10 条纯 `fts`"，但没测到**是哪个词面单元把它们拉进来的**。
不知道这一点就没法定本轮该动哪个变量——只能凭直觉列一串候选，然后花一整轮去扫。

结论先说：**四条发现里最重要的一条是"P3 的装置不能用来做 FTS 工作"。**

---

## 1. F0-1：中文 query 的词面竞争池只有 **66** 行，不是 50,066

| 读数 | 值 |
| --- | ---: |
| 装置物理行 | 50,066 |
| **含中文的行（= 中文 query 的词面竞争池）** | **66**（新 gold 40 + 旧 gold 26） |
| 含中文字符的 filler 原文 | **0 / 10,000** |

`pool-policy-filler-10k.json` 的 10,000 条全是英文——它的 `meta.purpose` 写着
"真实 cosine 分布 + 确定性回放到 50,000 候选"，**它是为语义腿造的**，从来不是为词面腿造的。
样例：`Android UI case 00-00: dark theme colors in the ConstraintLayout`。

后果，逐项实测：

| 返回行来源 | filler | gold |
| --- | ---: | ---: |
| 30 条词面锚点负例（109 行） | 13 | **96** |
| 61 条 relevance 正例（145 行） | **0** | 145 |

那 13 行来自锚点 query 里的**拉丁/数字单元**（混排段才会被切出拉丁串），中文 3 字窗口一行都碰不到 filler。

**含义（本轮的硬前提）：** df、bm25 饱和度、top-50 截断这三件事在 P3 装置上都不是生产规模下的读数。
一个真实的中文工作区里，`能不能` 这种功能词窗口会命中几乎每条记录；在这个装置上它只命中 2 条。
**FTS 安全策略轮次必须先建一份中文词面 filler 语料**，否则扫出来的任何参数都不可外推。

## 2. F0-2：中文 query 在 FTS 腿里**没有"词"这个概念**

`extractFtsSearchUnits` 有两趟：pass 1 推整段 / 整个 CJK 连续串 / 混排段里的拉丁串，
pass 2 用 3 字滑窗切长 CJK 串。对一条没有空格的中文问句，**pass 1 推出来的是整句**：

```text
query : 不同类型的记录能不能各设一条自己的地板线
pass 1: ["不同类型的记录能不能各设一条自己的地板线"]        ← 永远匹配不到任何文档
命中  : 自己的 / 的地板 / 地板线 / 能不能                  ← 全部来自 pass 2 滑窗
```

正例侧同样：**145/145 行全部只靠滑窗命中，含 pass-1 单元的 0 行。**

而滑窗是**跨词边界**的。实测命中单元里有一半根本不是词：

```text
锚点 sr-a01  自己的 / 的地板     锚点 sr-a02  能不能（唯一命中单元）
锚点 sr-a04  压缩的             正例 sr-r01  其中一 / 必须用 / 用同一
正例 sr-r04  语料里 / 个指标 / 指标会
```

`sr-a02` 是最干净的一例：整条 query 只有 `能不能` 命中，返回 2 条不相关记录。
**它不是"词面锚点命中"，它是"功能词碎片命中"**——而 P2 §4.1 那次改写只是把
"必然命中一个 10k 英文语料"的那批换掉了，没有、也不可能消除这个机制。

## 3. F0-3：一条返回通常只由**一个**单元造成

| cohort | 每 query 单元数（均/最大） | 每条返回命中的单元数（均/中位） | 只命中 1 个单元的行 |
| --- | ---: | ---: | ---: |
| 词面锚点负例 | 18.5 / 25 | 1.12 / 1 | **97 / 109** |
| relevance 正例 | 22.6 / 32 | 1.41 / 1 | 109 / 145 |

单元之间是 `OR`，且**没有任何覆盖度要求**：一条记录命中 18 个单元里的 1 个碎片就成为候选，
进 bm25 排名，再以 `1/(60+rank)` 进 RRF。这就是 P3 §4.1 那个"满页纯 fts"的完整因果链。

正例的 1.41 略高于负例的 1.12，是目前唯一能看到的量化差别。

## 4. F0-4：三条候选规则的曲线

**全部是描述性的，且受 F0-1 的装置限制。** 它们只用来判断"哪个方向值得进网格"，
**取值必须在新集 + 新装置上选**（与 P4.0 同一条纪律：探针不产出可采用的阈值）。
阶梯是先写死的固定刻度，不是从数据里挑的。

### 4.1 df 上限：在这个装置上**看不出效果**

| df/N 上限 | 锚点仍有命中的 query | 锚点页面行 | 正例失去全部单元 | 正例 gold 行保住 |
| ---: | ---: | ---: | ---: | ---: |
| 0.001 | 29/30 | 85/109 | 0/46 | 22/22 |
| 0.010 | 29/30 | 85/109 | 0/46 | 22/22 |
| 0.050 | 29/30 | 85/109 | 0/46 | 22/22 |
| 0.100 | 30/30 | 109/109 | 0/46 | 22/22 |

命中单元的 df/N 中位数只有 0.0001（锚点）/ 0.0000（正例），因为中文竞争池只有 66 条。
**这张表不可外推**：它测的是"在一个没有中文竞争的语料里 df 门槛没用"，
而不是"df 门槛没用"。中文 filler 建好后必须重测。

### 4.2 最少命中单元数：**有真实取舍曲线**

| 要求命中 ≥ N 个单元 | 锚点页面行 | 正例 gold 行保住 |
| ---: | ---: | ---: |
| 1（现状） | 109/109 | 22/22 |
| **2** | **12/109** | **14/22** |
| 3 | 1/109 | 6/22 |
| 4 | 0/109 | 2/22 |

≥2 把锚点页面行砍掉 89%，代价是 36% 的 gold 行。**这与 floor 的形状完全不同**——
P3 §4.2 里 floor 根本没有取舍曲线（假线索最高分 0.604 反超真答案 0.602），
而这里存在一段可以谈判的区间。目前唯一有这个性质的方向。

### 4.3 只承认 pass-1 单元：**当场否掉**

| 规则 | 锚点仍有命中的 query | 锚点页面行 | 正例 gold 行保住 |
| --- | ---: | ---: | ---: |
| 必须命中 ≥1 个 pass-1 单元 | 6/30 | 37/109 | **0/22** |

gold 行归零，因为 F0-2：对中文 query，pass-1 单元就是整句。这条路不用进网格。
（那 37 行与 6 条 query 全部来自拉丁/数字单元，与中文无关。）

## 5. 对新轮次的四条硬约束

1. **先建中文词面 filler 语料**（F0-1）。没有它，df / bm25 / 截断读数都不可外推。
2. **"单元覆盖度"是当前唯一有取舍曲线的候选方向**（F0-4.2），但取值必须在新集上选。
3. **不要把 pass-1/pass-2 之分当判别信号**（F0-4.3），对中文它不成立。
4. **df 上限保留为候选，但必须在中文竞争池上重测**（F0-4.1）；现在这张表既不能支持它、
   也不能否掉它。

## 6. 诚实边界

1. 本报告用的是 P3 已消耗集，**只做描述性测量**；任何数字都不得作为新轮次阈值的来源。
   三条曲线的阶梯是固定刻度（`0.001…0.2` 十进制 / `1…4` 自然数），先写后跑。
2. **所有曲线都受 F0-1 的装置限制**，尤其 4.1。4.2 的取舍曲线是在 66 条中文竞争池上量的，
   放到真实中文语料里两侧都会变——它证明"这个方向存在取舍空间"，不证明"≥2 是对的"。
3. 本诊断**没有跑语义腿、没有建向量、没有碰生产策略**，因此它不改变 P3 的任何读数，
   也不改变 C1 = 1.900 / P6 不通过 / Phase 3C 不通过。
4. `pass1Units()` 是按生产实现**重算**的分类函数，不是生产代码的一部分。
   它与 `extractFtsSearchUnits` 的 pass 1 逐条对应；若生产实现改动，这个分类会失效。
