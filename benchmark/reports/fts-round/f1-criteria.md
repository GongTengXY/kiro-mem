## 0. 三十秒版本

一条 hard-negative 只要与某条记录有**一个 3 字滑窗碎片**重合就能进页面，语义 floor 管不到它
（P3：floor 0.325 上 `sr-a01` 仍返回满页 10 条纯 `fts`）。本轮测的是**词面准入**：

- **V1 单元覆盖度**：一条记录要进候选，光命中一个碎片够不够；
- **V2 单元 df 上限**：`能不能` 这种几乎命中全语料的功能词窗口该不该有投票权。

两件事在跑之前必须先解决：**装置里没有中文竞争池**（F0-1：filler 含中文 0/10,000，
中文 query 的竞争池只有 66 行），以及 **V1 的实现形状**（F1 实现探针：SQL 内联要 16.7× 基线，
出局）。本文把这两件事和门、召回保护线、选择规则一次性写死。

## 2. 网格：16 个 arm

```text
V1  windowCoverageRatio  r ∈ { 0, 0.10, 0.20, 0.30 }
V2  unitDfRatioCeiling   d ∈ { 1.00, 0.30, 0.10, 0.03 }
arm id 格式：r<r>-d<d>          例：r0.20-d0.10
基线 arm：r0-d1.00              ← 两个变量都关闭，必须逐条复现今天的页面

```

### 2.1 V1 的形式：豁免 + 比例，不是全局 ≥N

plan §4.2 明写覆盖度**不能**是"全局 ≥N 个单元"——那会连 LIKE 回退分支、专有名词、路径、
数字一起打死。本轮的形式：

**单元先分两类**（按生产 `extractFtsSearchUnits` 的两趟结构重算，与 F0 的 `pass1Units()`
同一形状）：

| 类 | 是什么 | 例 |
| --- | --- | --- |
| **精确单元** | pass 1 推出的整段 / 整个 CJK 连续串 / 混排段里的拉丁串 | `src/db/index.ts`、`kiro-mem`、`0.197`、`FTS5`、整句 |
| **滑窗单元** | pass 2 的 3 字滑窗 | `自己的`、`能不能`、`的地板` |

**准入规则**（记 `W` = 该 query 的滑窗单元数）：一条记录被准入 ⟺

```text
(a) 它命中 ≥1 个精确单元        ── 专有名词 / 路径 / 数字 / 版本 / 短查询走这条
或
(b) 它命中的滑窗单元数 ≥ ceil(r × W)   ── 中文问句走这条
```

两条是 **OR**，这是有意的，理由与 F0-4.3 相反方向：F0 实测"只承认 pass-1 单元"会让正例
gold 行归零（0/22），因为中文 query 的 pass-1 单元就是整句。所以 (a) 不能单独成为规则；
它在这里的作用是**豁免**，让 §4.2 的五类召回保护线不被 (b) 波及。

三条边界必须与规则一起读：

1. **`W = 0` 时 (b) 恒不成立**，此时准入完全由 (a) 决定 = 今天的行为。纯拉丁 query、
   路径 query、数字 query 因此**不受 V1 影响**。
2. **LIKE 回退分支（query 短于 3 字）完全不经过 V1。** 那条分支没有单元，覆盖度无意义。
3. **`r` 与 `ceil` 的交互对短中文 query 天然宽松**：`W = 2` 时 `ceil(0.30 × 2) = 1`，
   即任何 `r ≤ 0.5` 都不约束它。这是保护，不是缺陷；但也意味着**V1 对短中文 query 无效**，
   G2 若在这类 query 上失败，V1 不是解。

**(a) 的已知代价，先写下来**：混排 query（`kiro-mem 的地板线是多少`）里 `kiro-mem` 是精确单元，
于是任何命中它的记录都被 (a) 豁免——**包括词面负例**。这是"保护专有名词召回"的直接对价。
判据不因此修改规则；**§11 的预测二把它写成一条可验证的预测**。

### 2.2 V1 的实现形状：候选窗口内准入，`K` 由 §2.2.1 的阶梯选定

由 F1 实现探针裁定（`f1-impl-probe.md` §2、§5）：

| 形状 | 最坏一格相对基线（msMin） | 处置 |
| --- | ---: | --- |
| SQL 内联（`instr` 求和进 WHERE） | **+1657.64 ms（16.7×）** | **出局** |
| 逐单元全量 MATCH 探针 | +137.42 ms，且随 `Σ df` 涨 | **精确语义的参照实现；也是 K 阶梯的终点** |
| **候选窗口内准入（K 阶梯）** | K=200 时 **+4.60 ms，与语料规模无关** | **采用，但 K 由 F2 按 §2.2.1 选定** |

落地契约（写死，F3 不得偏离）：

1. FTS 腿内部取前 `K` 个 bm25 候选，在候选内做单元归因与覆盖度过滤，
   **返回至多 50 条**给检索内核；
2. 因此 **V4（返回内核的 50）保持冻结**，`K` 是 V1 的实现常量，两者不纠缠；
3. `K` **不是网格变量**（plan §3 第 8 条）。它**只能由 §2.2.1 的正确性阶梯选定**，
   **不得由任何门的读数选定**，F3 全程不得改动它；
4. 每个 arm 必须报告**页面缩水**（因准入过滤而少于 `limit` 的返回）。

#### 2.2.1 `K` 的语义必须精确：F2 的预登记阶梯 + S7 资格门（r2 新增）

**r1 在这里留了一个未受控的第三变量**（F1 复核第 1 项）：候选窗口是**近似**语义——
排在 `K` 之后、本该通过 V1/V2 的记录进不了页面。r1 的 S7 只要求"记录差集"，
没有要求它为 0，于是 K 截断造成的页面变化可能被误归因给 V1/V2。

**修正：`K` 的取值由 F2 在冻结的中文装置上按下面这条阶梯选定，判定只用正确性，不看任何门。**

```text
阶梯（先写死，不得增删、不得改序）：K ∈ [200, 1000, 5000, EXACT]
  EXACT = 逐单元全量 MATCH 探针（形状 B），差集为 0 由构造保证

选择规则：取阶梯中**最小**的 K，使得在 16 个 (r, d) 设置 × 全部 120 条 query 上
          与 EXACT 的**候选差集逐 query 为 0**。
```

三条约束：

- **判定即 S7 资格门**：差集必须**逐 query 为 0**。任何非零差集意味着该 `K` 不合格，
  阶梯前进到下一档；**在 S7 通过之前不得跑网格**。
- **终点由构造保证**：`EXACT` 的差集恒为 0，因此阶梯不会走空。代价是成本——
  实测 `+137.42 ms` 且随 `Σ df` 涨（`f1-impl-probe.md` §2），
  它必须与 §6.6 的性能资格门一起判定；若连 `EXACT` 都过不了性能门，
  **报"本轮实现形状不可行"并停下取裁定**，不得改用近似语义继续跑。
- **`K` 单独冻结**：F2 选出的 `K` 与其自证读数写入 `f2-freeze.json`（由 `freeze-util.ts` 生成，
  引用 `f1-freeze.json`）。F1 冻结的是**阶梯与选择规则**，不是某个 `K` 值——
  这样"K 是怎么定的"在证据链里有独立记录。

**r1 那条"K=200 在 P3 装置上丢 0 条"的读数就此降级为背景**：它是在中文竞争池只有 66 行的
语料上量的，不作为 `K = 200` 的依据，只解释为什么阶梯从 200 起步。

### 2.3 V2 的形式：丢掉的单元同时退出 OR 与覆盖度

`unitDfRatioCeiling = d`：单元的 `df / scopeSize > d` 时**丢掉该单元**。丢掉意味着：

1. 它不进 OR 候选生成表达式；
2. 它既不计入覆盖度的分子，也不计入分母（`W` 按存活的滑窗单元数算）。

两处同时丢，是为了让候选窗口不被高 df 单元灌满——只从覆盖度里丢、仍留在 OR 里，
候选池会继续被功能词碎片占满，窗口截断的压力就转移到了正例身上
（而 §2.2.1 的 S7 会把这种压力直接变成一次阶梯前进，即更高的成本）。

**退化边界（写死）**：若一条 query 的**全部**单元都被 V2 丢掉，FTS 腿返回空，
**不得回退到 LIKE 分支**。LIKE 回退会绕过整个准入机制并按子串把记录全拉回来，
等于让 V2 在最该生效的地方失效。这条会造成召回损失，由 G4 与召回保护线看着。

**V2 的成本必须预留**：df 是 scope 级统计，无法只在 `K` 行内完成。实测最坏一格
**99.27 ms**，与基线同量级（`f1-impl-probe.md` §4）——plan §2 写的"成本低"已被实测否定。
它计入 §6.6 的性能资格门。

## 3. 装置

### 3.1 中文词面 filler 语料（本轮最大的新增工程量）

F0-1 是本轮的硬前提：**没有中文竞争池，df / bm25 / 截断读数都不可外推。**

| 项 | 规定 |
| --- | --- |
| 语言 | **中文正文**（进 FTS 的那一面） |
| 规模 | **10,000 条独立记录**，与英文 filler 同量级；**并列播种，不替换英文那 10,000 × 5 副本** |
| 副本 | 中文侧**不做副本回放**（英文侧的 5 份副本保留，保证语义腿既有读数可比） |
| 物理行 | 40 新 gold + 26 旧 gold + 50,000 英文 + 10,000 中文 = **60,066** |
| 向量 | 中文记录按生产协议走**英文镜像**（`observation_semantic_texts` 存英文，向量在 `semantic-en-v1` 空间）。镜像由**同一套模板的英文面**确定性生成，**不调 ACP**——它是 filler，不是 gold |
| 词面纪律 | 沿用 `phase3b-criteria.md` §3.4 的禁用表：不得与任何 gold 记录共享标识性 concept / 文件基名 |
| 功能词 | **必须自然包含**中文功能词，词表与生成占比按 §3.1.1 **预登记并冻结**；否则又造出一个 df 恒为 0 的假语料 |
| 生成方式 | 模板 × 领域 × 序号，单一 `seed`，确定性可复算；生成脚本与语料一起冻结 |
| 自证 | 见 §7 的 S2 / S3：物理行数、含中文行数、**逐词 df/N 与冻结占比的偏差**、禁用表违规数 = 0 |

#### 3.1.1 功能词表与生成占比（预登记，冻结后不得反向塑造）

**为什么要冻结占比**（回应 F1 复核的附带改进）：只要求"至少一个功能词 df/N ≥ 0.10"
是一条模板轻易机械满足的检查，它证明不了分布自然，也拦不住"为了让某个 `d` 刻度好看"
而回头调语料。因此把词表与**目标占比**一起写死，S3 逐项核对。

| 功能词 | 目标生成占比（**分母 = 10,000 条中文记录**） |
| --- | ---: |
| `能不能` | 0.10 |
| `有没有` | 0.10 |
| `是不是` | 0.08 |
| `为什么` | 0.08 |
| `的时候` | 0.25 |
| `的模型` | 0.05 |
| `会不会` | 0.06 |
| `什么时候` | 0.05 |

占比的来源必须与数字一起读：它们是**先验选定的一组量级**，用来让功能词窗口的 df/N 落在
"常见虚词"与"低频短语"之间，**不是**从任何真实工作区语料统计出来的，也**不得**被 V2 的刻度
引用（§2.4 的刻度是等比铺开的独立规则）。S3 判定实测 `df/N` 与上表的**相对偏差 ≤ ±20%**。

这张表连同 `seed`、模板集、禁用表一起进 `f1-freeze.json` 的 payload。

**这里最容易做假**：如果中文 filler 的词面分布与真实工作区不像，扫出来的 V1 / V2 取值就
不可外推。§3.1.1 的冻结占比 + S3 的逐词核对是对这一点的**约束**，不是证明——
语料自证的是"分布非退化且未被反向塑造"，**不是**"与真实中文工作区同分布"（§12 第 3 条）。

## 4. 新校准集（**只服务本轮**，不得给语义研究或轨道 A 选参）

### 4.1 组成

| 词面负例：**同词不同事** | **15** | G2 | 同上 + `other_meaning_basis` |
| 词面负例：**旧状态混淆** | **10** | G2 | 同上 + `no_change_record_basis` |
| 召回保护线：短查询 / 专有名词 / 路径 / 数字 / 历史状态 | **各 8 = 40** | §6.5 | `protection_class` / `primary_gold` / `annotation_basis` |
| 新记录（gold 载体） | **40 条** | 全部 **80 条正例**（40 relevance + 40 保护线）的 `primary_gold` 载体 | `fact_source`（沿用 P2 §2.2） |

合计 **120 条 query**。词面负例三类共 40 条，**每条都必须带实测 `ftsCount ≥ 1` 的确认**
（在本轮的中文装置上实测，不是在 P3 装置上）。

**gold 载体的两条约束**：

1. 40 条新记录是**唯一**的 `primary_gold` 来源，`primary_gold` 必须是本轮新记录（从未当过 gold）；
   一条新记录**可以**同时是多条 query 的 `primary_gold`（relevance 与保护线都算）。
2. **每条新记录至少要在一条 query 中作为 `primary_gold`**（沿用 P2 裁决 1.4，校验脚本硬失败）。
   旧 26 条只能进 `acceptable_gold`。

### 4.2 三类词面负例的判定口径（plan §4.3 的落地）

| 类 | 定义 | 冻结时必须逐条写明 |
| --- | --- | --- |
| **错误前提** | 词面命中，但问题假设的事实不存在 | 那个前提**为什么不存在**：代码 / 报告 / commit 出处 |
| **同词不同事** | 同一个词在语料里指另一件事 | 该词在语料里**实际指什么**，与 query 问的**如何不同** |
| **旧状态混淆** | 把已变更的状态当现状问，且**语料里没有那条变更记录** | **为什么语料里没有能回答它的记录** |

第三类与 P2 判据 §4.2 已裁定的 **stale-state relevance 只差一个事实判定**：
有变更记录 → 它是 relevance（必须返回那条变更记录）；没有 → 它是负例。
**逐条写明缺哪条记录**，否则会把正确召回算成误召回（P2 §4.4 同一条纪律）。

### 4.3 相关性判定与 `acceptable_gold`

沿用 P2 判据 §4.1 的唯一口径：**若某条 Observation 能实质性地确认、否定或解释 query 所问的
事实，它就是该 query 的相关记录。** `acceptable_gold` 在冻结前穷举；
**不得**在跑完之后以"这条其实也算相关"为由把某条返回项移出非 acceptable 计数。

### 4.4 四档分层：覆盖**全部 80 条正例**（r2 修正）

**r1 在这里与上游裁定不一致**（F1 复核第 3 项）：§6 写 G4 覆盖"全体正例"，
而 §4.4 只给 40 条 relevance 分层，40 条召回保护线没有进四档。裁定原文是
"**全体正例，四档分层**"，缩小 G4 的覆盖范围**必须另取裁定**，不得在 F1 内自行改门形状。

因此分层对象是 **80 条正例 = 40 relevance + 40 召回保护线**，两类用**同一个**分层键：
query→自己 `primary_gold` 的最高余弦。

沿用 P2 §7.2 的合法产出顺序，**不得倒过来**：

1. 先按各自规则成批撰写 40 条 relevance query 与 40 条保护线 query，
   **撰写时不看任何余弦**；
2. 全部写完后**一次性**测量全部 80 条的 query→自己 `primary_gold` 最高余弦，
   分四档 `[<0.200) / [0.200,0.310) / [0.310,0.400) / [≥0.400)`；
3. 任一档在 **80 条并集**上不足 **8 条**时**只补写、不删除**已有条目；
   **补写只发生在 relevance 侧**——保护线五类各 8 条是 §4.1 冻结的配额，
   不得为了填档而改动它的类内构成；
4. 分层结果随数据一起冻结。**必须冻结三套条数**：80 条并集的四档、40 条 relevance 的四档、
   40 条保护线的四档。F3 的 runner 必须复现这三套（S5）。

**保护线的类别配额与四档分层是两个正交切面**，两者都保留：G4 按四档判定（裁定要求的覆盖范围），
§6.5 按五类判定（plan §4.2 要求的保护线）。**后者是额外过滤器，不替代前者。**

### 4.5 `semantic_query_en`

每条 query 的英文形由**生产 ACP 译者**（`kiro-mem-compressor`，与记录侧同一份 prompt 规则、
分开的进程调用）产出，镜像文件与数据一起冻结，口径沿用 P2。被生产护栏
（`checkSemanticEnQuery`）拒绝的条目必须重译至 **0 拒绝**，否则该 query 的语义腿整条不跑，
G1 / G3 的读数会掺进一个与本轮无关的失败原因。

### 5.1.1 四档分层读数：**80 条正例**（r2 修正）

## 6. 门的机械判定（G1–G4 + 召回保护线）

门的形状由 `gate-shape-ruling.md` 裁定（Q1 = b / Q2 = b），**L1–L4 已作废，不得沿用**。
本节只写"怎么算"。

| 门 | 覆盖 | 地位 |
| --- | --- | --- |
| **G1** 排序污染门 | 全体正例（40 relevance + 40 保护线 = **80**） | **主门** |
| **G2** 容量门 | 所有没有 `acceptable_gold` 的 query（= **40** 条词面负例） | 辅门 |
| **G3** 标记门 | 全体 cohort（**120**） | 辅门 |
| **G4** 非回退线 | **全部 80 条正例**，四档分层（§4.4） | **与 G1 同等** |
| **召回保护线** | 40 条，五类各 8 | **与误召回门同等，不是附注** |
| **S7** `K` 语义资格门 | 16 设置 × 120 query 的候选差集 | **前置门：不通过不得跑网格**（§2.2.1） |
| **性能资格门** | 完整 search p95 | **候选资格门**（§6.6，r2 新增） |

后两项**不改变 G1–G4 的形状**，它们是 F1 复核要求补的资格过滤器：
S7 管"读数是否可归因"，性能门管"选出来的 arm 是否跑得动"。

### 6.1 G1：排序污染门

对每条正例 query：令 `p` = 页面上第一个 `primary_gold` 的位置；统计位置 `< p` 且不在
`acceptable_gold` 里的条数。**全体求和必须为 0。**

```text
p 不存在（primary_gold 不在页面）→ 该 query 记 0，并单独计入 primaryAbsent
```

公式与阈值**与 P3 的 N3 完全相同**（裁定第 1 项：G1 是"提升为主门"，不是收紧）。
`p` 不存在时记 0 正是那个**可被利用的退化解**——把所有结果连同 gold 一起压掉，G1 反而通过。
**G4 与召回保护线是它的资格过滤器**，不是补充说明。

报告模板必须把两件事分开（裁定 §3.2 的口径纪律）：

| 读数 | 含义 |
| --- | --- |
| `pollutionCount` | 排在 `primary_gold` 前的非 acceptable 结果**数** |
| `actualDisplacement` | **相对基线臂**的反事实：该 query 在本 arm 的 `primaryRank` 差于基线，且中间插入的是非 acceptable 结果 |
| `primaryAbsent` | `primary_gold` 根本不在页面的 query 数 |

**不得把 `pollutionCount` 描述成"实际位移次数"。** 它们是两个数。

### 6.2 G2：容量门

40 条词面负例，**整页跨来源** `distinctContent` **≤ 2**，**逐条判定，不取平均**。

- 跨来源：`fts` / `hybrid` / `semantic` 一视同仁。**不得因为某条返回的来源是 `fts` 就把它
  排除在计数外**——这正是 P3 的 N1 被删掉的原因：来源不是相关性标签（裁定 Q5）。
- **`2` 不得依据本轮数据调高**（裁定 Q4）。它早于 P3、由 Phase 2B 预登记选择产生，
  但它**不是独立安全证据**；本轮只是沿用，不重新论证。
- 逐条报告 `physicalRows` 与 `distinctContent` 两套，判定用后者。

### 6.3 G3：标记门

120 条全体 cohort 的每一条返回项：

1. **`match_source` 必须正确**。机械重算规则（`bigramAux = false`，本轮无 bigram 腿）：

   ```text
   在 ftsRank 且在 semanticRank  → hybrid
   只在 ftsRank                 → fts
   只在 semanticRank            → semantic
   ```

   重算值与返回值逐条比对，出现任一不一致即 G3 失败。
2. **semantic-only 受 cap 约束**：每条 query 的 `match_source = semantic` 条数 **≤ 2**。

### 6.4 G4：分层非回退线（**80 条正例**）

覆盖 **全部 80 条正例**（40 relevance + 40 保护线，§4.4）。四档
`[<0.200) / [0.200,0.310) / [0.310,0.400) / [≥0.400)`，每档在并集上 ≥ 8 条。
相对**基线臂 `r0-d1.00`**：

```text
∀档 b:  arm.primaryHitAt5[b] >= baseline.primaryHitAt5[b]
        arm.primaryMRR[b]    >= baseline.primaryMRR[b] - 1e-9
```

`1e-9` 只为吸收浮点表示误差，**不是容差**：MRR 的实质要求是"不得低于基线"。
判定用**并集**那一套；relevance 与保护线各自的四档**必须同时报告**，用于归因回退来自哪一侧，
但**不参与判定**（避免同一件事被判两次）。任一档回退即该 arm 淘汰（过滤器，不是排序键）。

### 6.5 召回保护线

五类各 8 条，**每类单独判定**，相对基线臂：

```text
∀类 c ∈ {短查询, 专有名词, 路径, 数字, 历史状态}:
   arm.primaryHitAt5[c] >= baseline.primaryHitAt5[c]
   arm.primaryMRR[c]    >= baseline.primaryMRR[c] - 1e-9
```

**任一类回退即该 arm 淘汰。** 写成过滤器而不是排序键的理由与 P3 §7 第 3 步相同：
排序键会允许"用容易类的收益换掉难类的损失"，而这五类正是 V1 / V2 结构上最可能打坏的地方。

**它与 G4 是两个正交切面**（§4.4 末段）：G4 按余弦四档、保护线按类别，两者都必须通过。
保护线**不替代** G4 的覆盖范围。

三条口径提醒：

1. **短查询类**（< 3 字）走 LIKE 回退，V1 / V2 都不作用于它。它在这里的作用是**回归锚点**：
   若它回退，说明实现改动漏到了不该改的分支。
2. **历史状态类**是 stale-state **relevance**（P2 判据 §4.2 已裁定），必须返回变更记录。
   **不得**把它标成负例。
3. 五类的 `primary_gold` 在冻结时确定，不得事后调整。

### 6.6 性能资格门（r2 新增）

**r1 缺这道门**（F1 复核第 4 项）：探针已测到 V2 最坏额外约 **99.27 ms**，
而完整 search 的既定预算是 **p95 < 300 ms**，且 50,000 行装置上的既有 p95 已达
**203–260 ms**（`phase3c-submission.md`，README 限制表同一读数）。
没有性能门意味着可能选出一个安全但跑不动的 arm。

判定用 §5.6 的完整 search 读数，**在中文完整装置（60,066 行）上测**：

```text
主判定：arm.p95 < 300 ms
```

**基线已超预算时的预登记分支**（必须先写下，否则跑完之后无法归因）：

- 若**基线臂** `r0-d1.00` 的 p95 已 ≥ 300 ms，则该装置的绝对预算**在本轮不可达**，
  与 V1/V2 无关。此时性能门改为**相对判定**：`arm.p95 <= baseline.p95`；
- 同时**必须**把"60,066 行装置上基线即超预算"作为**独立缺陷单独登记**，
  写进 F4 收口报告与 README 的限制表候选项；
- **不得**用这条分支豁免 V1/V2 的新增成本——相对判定只允许"不比今天更慢"，
  不允许"因为今天也慢所以变慢没关系"。

`EXACT`（§2.2.1 阶梯终点）同样受这道门约束。若 `EXACT` 是唯一能让 S7 通过的实现，
而它过不了性能门，则**报"本轮实现形状不可行"并停下取裁定**，不得退回近似语义继续跑。

## 7. 结构自证（S 系列）

不是策略门，是"这台仪器有没有量对东西"。**任一项失败则该次运行的全部读数作废。**
S1–S3 属 F2（跑在 F3 之前），S4–S8 每个 arm 都要出。

| 项 | 阶段 | 检查 |
| --- | --- | --- |
| **S1** | F2 | 冻结记录逐项 SHA 一致，`frozen === true`。**计数标签由 `benchmark/freeze-util.ts` 的 `verifyFreezeRecord()` 生成**（形如 `判据 1/1 + 输入 N/N`），脚本不得自己拼计数字符串 |
| **S2** | F2 | 物理行 **60,066**；scope 向量 = 60,066；跨 scope 泄漏 = 0；`degraded` = 0；协议全部 `semantic-en-v1`；英文 query 被生产护栏拒绝 **0/120** |
| **S3** | F2 | **中文语料自证**：含中文行数 = 10,000；禁用表违规 = 0；**逐个报告 §3.1 预登记功能词表里每一个词的 `df / 中文记录数` 与 `df / scopeSize`**，前者与冻结的生成占比逐项比对（见下） |
| **S4** | F2 | 40 条词面负例在**本装置**实测 `ftsCount ≥ 1`（不得引用 P3 装置的读数）；40 条 relevance 与 40 条保护线的 `ftsCount` 分布一并报 |
| **S5** | F3 | **三套**四档条数复现冻结值：80 条并集、40 relevance、40 保护线（§4.4 第 4 条） |
| **S6** | F3 | **恒等锚点**：基线臂 `r0-d1.00` 的逐 query 返回页面与 `DEFAULT_RETRIEVAL_POLICY` 下的生产实现**逐条相同** |
| **S7a** | **F2，前置门** | **`K` 的语义资格门**（§2.2.1）：在 16 个 `(r, d)` 设置 × 全部 120 条 query 上，候选集与 `EXACT` 的差集**逐 query 为 0**。**不通过则不得进入 F3**；按阶梯前进后重测 |
| **S7b** | F3，每 arm | 同一比对在实际 arm 运行中复查，差集仍须**逐 query 为 0**。出现非零 → **该次运行全部读数作废**（不是只标注该 arm） |
| **S8** | F3 | 每个 arm 的逐 query `semanticOnly` ≤ 2；`V2 丢空` 的 query 逐条确认 FTS 腿返回空且**未**走 LIKE 分支（§2.3） |
| **S9** | F3 | 每个 arm 输出 §5.6 的完整 search p50/p95/p99 与分段耗时；基线臂同口径读数必须一起出，否则性能门无法归因 |

**S3 的形式（r2 加强，回应复核的附带改进；r3 修正分母口径）**：r1 只要求"至少一个功能词
df/N ≥ 0.10"，而模板很容易机械满足这一条，证明不了分布自然。改为：

1. §3.1 的功能词表**逐个**报告 `df`、`df / 中文记录数`、`df / scopeSize`；
2. **比对口径是 `df / 中文记录数`**（= §3.1.1 的生成占比，分母 10,000），
   逐项偏差超过 **±20%（相对）** 即失败——这道检查抓的是"语料被后续需要反向塑造"；
3. **`df / scopeSize`（分母 60,066）单独报，不参与比对**：它是这些功能词在整个 scope 上的
   真实竞争强度，比生成占比小约 6 倍（因为 50,000 条英文 filler 一个中文字都没有）。
   **两个分母必须分开写**，混用会把"语料合规"与"竞争强度"两件事说成一件；
4. **禁止反向塑造**：语料一经冻结，不得因为任何 arm 读数、或为了让某个 `d` 刻度好看而重新生成
   （§9 第 12 条同一条纪律）。

**r3 为什么改这一条**：`df / scopeSize` 与生成占比差一个 6 倍因子（`的时候` 生成占比 0.25，
但 `2500 / 60066 ≈ 0.042`），拿 ±20% 去比对必然全项失败。这是 r2 判据自身的口径缺陷，
在跑 F2 之前发现并修掉，**不涉及任何读数**。

**S6 的可行性已被实测**：F1 实现探针在 `minUnits = 1` 上验证过四种形状与生产实现
**139/139 逐条一致**，所以 `r = 0` 的恒等要求不是一句期望。

## 8. 确定性选择规则（先写后跑）

**必须由脚本计算**（`benchmark/select-fts-round-arm.ts`），不得手工抄表。

```text
前置条件（不满足则不进入选择，也不得跑网格）：
  P0  S7a 通过：在 F2 选定的 K 上，16 设置 × 120 query 的候选差集逐 query 为 0（§2.2.1）
  P1  S1–S4 全部通过（装置自证）

输入：16 个 arm 的读数
基线：baseline = r0-d1.00（两个变量都关闭 = 今天的生产行为）

1  结构排除：candidates = { arm : arm ≠ baseline }
      理由：基线是参照，不是候选。它必然通过所有"不得回退"，选它等于什么都没做。
2  安全过滤：feasible  = { arm ∈ candidates : G1 ∧ G2 ∧ G3 全部通过 }
3  资格过滤：eligible  = { arm ∈ feasible :
                            ∀档 b：G4 不回退  ∧  ∀类 c：保护线不回退
                            ∧ 性能资格门通过（§6.6） }
4  eligible 为空 → 输出「本轮没有安全 arm」，结束。
      不得下调任何门、不得删掉保护线中的任何一类、不得放宽 G2 的 2、
      不得为了让某个 arm 进候选而放宽性能门或改用近似语义。
5  否则按字典序取最大：
     ① primary hit@5 最大
     ② primary MRR 最大
     ③ 准入更强者优先：r 更大；r 相同则 d 更小
     ④ arm id 字典序最小        # 纯为消除并列，保证可复算
```

第 3 步是过滤器不是排序键，理由见 §6.4 / §6.5。**性能门也写在第 3 步而不是第 5 步的排序键里**：
写成排序键等于允许"用相关性收益换延迟"，而延迟预算是既定发布门，不是可交易项。
第 5 步 ③ 的理由：走到这一步说明门与召回读数完全相同，此时更强的准入在**历史上失败过的
那一侧**（误召回）留更多余量。

**没有安全 arm 就报本轮不通过**（plan §3 第 9 条）。

## 11. 三个必须在跑之前写下的预测

写在这里的唯一目的：**跑完之后没人能声称这三件事是事后解释。**
它们**不改变**任何门的判定，也不构成放宽的理由。

**预测一：G2 在"同词不同事"那 15 条上最可能不通过。** V1 管的是"命中几个单元"，
而同词不同事的负例与真记录共享的往往**不止一个**滑窗（同一个词在两处出现，周边字也相近），
因此提高 `r` 未必能把它们挡在外面。若失败集中在这一类，结论是**覆盖度不是这一类的解**，
需要的是内容级证据而不是词面计数。

**预测二：`(a)` 精确单元豁免会让混排锚点负例继续进页面。** §2.1 已写明这是保护专有名词
召回的直接对价。验证读数是 §5.4 的"`(a)` 豁免命中数"——若 G2 的失败条目里豁免命中数占多数，
那么**V1 的形式本身有上限**，而不是 `r` 取小了。

**预测三：V2 与"历史状态"保护线冲突。** 那 8 条是完整中文问句，它们的判别信号恰恰落在
中等 df 的滑窗上；`d` 越小，被丢掉的单元越多。若保护线在 `d = 0.03` 上回退而 G2 在
`d = 0.30` 上不通过，说明**两侧没有公共可行区间**——那和 P3 一样是个有信息量的结论，不是失败。

**plan §2 已预登记的整体分支**：本轮完全可能得出"V1 与 V2 都不足以同时满足门槛与召回保护线"。
按 §8 第 4 步如实报"本轮不通过"。

## 12. 诚实边界

1. **本判据在看过 F0 与 F1 实现探针之后写成。** 两者都在**已消耗的 P3 集**上测量，
   因此只能支持"选哪个方向、用哪种实现"，**不能证明本轮的门有效**——与 `gate-shape-ruling.md`
   §4 第 2 项同一条边界。
2. **新校准集只服务本轮。** 不得拿去给语义研究或轨道 A（G1 候选级排序取证）选参。
3. **中文 filler 是模板生成的合成语料**，不是真实工作区抽样。它自证的是"df 分布非退化"，
   **不是**"与真实中文工作区同分布"。V1 / V2 的取值外推到真实工作区时受此限制。
4. **中文 filler 的向量走模板英文面，不经 ACP。** 它是 filler 而非 gold，这条省的是成本；
   代价是它的英文面比真实 ACP 译文更规整，语义腿在中文 filler 上的分布因此偏乐观。
   本轮的门都不依赖 filler 的语义分数，但 `comparableVectors` 这类读数会受影响。
5. **撰写者、fixture 作者、判定者是同一人**（AI 起草 + 操作者审阅），与此前各轮同一条边界。
   缓解：G1–G4 全部是机械计算，选择由脚本执行。
6. **`p95 < 300 ms` 这个预算是在 50,000 行装置上量出来的**（`phase3c-submission.md`：
   p95 203–260 ms），而本轮装置是 **60,066 行**。因此基线臂在本装置上超预算是**可能的**，
   且那与 V1/V2 无关——§6.6 的相对判定分支正是为此预登记的，而不是为了给新增成本留后门。
7. 本判据引用的 `plan/V3/*.md` 不在版本库中（`.gitignore` 的 `plan` 规则，按项目意图只保留本地），
   因此那些引用需要本地文件配合才能核对；`benchmark/reports/**` 与 `benchmark/dataset/**`
   的引用不受此限。
