# FTS 安全策略轮次 F1 实现探针：V1 / V2 的实现形状与成本

> 日期：2026-08-13
>
> 角色：**实现探针。描述性，不产出任何阈值、不选任何参数、不是 arm。**
>
> 脚本：`benchmark/probe-fts-coverage-cost.ts` → `f1-impl-probe.json`
>
> 装置：P3 冻结装置逐行相同（50,066 行），SHA 逐项校验，**不建向量、不跑语义腿**。

---

## 0. 为什么在写判据之前先跑这个

plan §2 的 V1 一行写着：*"FTS5 的 `OR` 表达式本身表达不了『至少 N 个』，要么逐单元探针后过滤，
要么改成组合表达式。**成本必须实测**"*。判据里 V1 的形式必须是**可实现且已知成本**的形式，
否则 F3 会扫一个跑不动的网格，而那要到 F3 才发现。

本探针只回答两个问题：**哪种实现形状能在预算内跑**，以及**它与精确语义差多少**。
它**不**回答"覆盖度门槛该定多少"——那是判据在新集上的事。

---

## 1. 三种形状（plan §2 点出的两条路 + 一条便宜路）

| 形状 | 做法 | 语义 | 成本的自变量 |
| --- | --- | --- | --- |
| **A** SQL 内联 | `MATCH` 的 OR 表达式 + 9 列 `instr()` 求和 `>= N` 进 `WHERE` | **精确**：`LIMIT` 作用在过滤之后 | 匹配行数 × 单元数 × 列数 |
| **B** 逐单元全量探针 | 每个单元一次 MATCH 取全部 rowid，JS 聚合计数，再按 bm25 顺序取前 N 个存活者 | **精确**（与 A 等价） | `Σ df` |
| **C** 候选窗口内准入 | 先按今天的 OR + bm25 取前 `K` 条，只在这 K 行上归因、过滤，再取前 `limit` | **不精确**：排在 `K` 之后、本该通过覆盖度的记录进不了页面 | `K`（与语料规模无关） |

另有一条**基线臂 P**：今天的生产 `searchObservationsFts`。没有它，OR 候选生成与 bm25 排名的
既有开销会被记到 V1 头上。

## 2. 成本：A 出局，B 与语料一起涨，C 的新增成本与语料规模脱钩

全部 139 条 query（真实 131 + 合成 8）汇总，`minUnits = 2`，单位 ms：

| 形状 | min | p50 | p95 | max |
| --- | ---: | ---: | ---: | ---: |
| **P 基线** | 0.11 | 0.43 | 9.59 | 157.82 |
| **A** | 0.20 | 0.43 | 68.04 | **1871.18** |
| **B** | 0.24 | 0.69 | 15.09 | 277.53 |
| **C**（K=50） | 0.11 | 0.64 | 12.65 | 140.18 |
| **C**（K=200） | 0.11 | 0.62 | 13.72 | 152.65 |

**最坏一格相对基线的新增成本**（msMin 差）：

| 形状 | 新增 | 相对基线 |
| --- | ---: | ---: |
| A | **+1657.64 ms** | **16.7×** |
| B | +137.42 ms | 2.3× |
| C(50) | **+0.26 ms** | 1.00× |
| C(200) | +4.60 ms | 1.04× |

三条结论：

1. **A 出局。** 1763 ms 对 300 ms 预算不是"偏高"，是差一个数量级；而且它把每个匹配行的成本
   乘上 `单元数 × 9 列`，语料越大越差。
2. **B 能跑，但它的新增成本随 `Σ df` 涨。** 这一格 `Σ df = 188,147` 是 3 条合成 query 造出来的；
   真实中文语料里 `能不能` / `有没有` 这类功能词窗口会**同时**高 df，而一条中文 query 平均 18.5 个
   单元（F0-3），所以 `Σ df` 会比这里更大。它不是一个与语料规模脱钩的界。
3. **C 的新增成本由 `K` 决定，与语料规模无关**（+0.26 / +4.60 ms）。代价不在时间上，在语义上：
   准入被 bm25 排名截断限制。

### 2.1 合成组是怎么造的，以及它为什么能在中文语料建好之前给出上界

**成本与语言无关**：三种形状的成本由匹配行数、单元数、`Σ df` 决定，与那些行是什么语言无关。
F0-1 已登记该装置的中文竞争池只有 66 行，所以**中文 query 的匹配行数不可外推**——
于是本探针另造一组**高 df 拉丁单元** query（英文 filler 提供 df 直到全表），
把"中文语料建好之后才会出现的匹配行数"现在就量出来：

```text
syn-multi3   22 单元  匹配 50,028  Σdf 150,033   test=50014 / the=50001 / case=50000
syn-multi6   25 单元  匹配 50,028  Σdf 167,239   + layout=6670 / cache=5765 / build=4771
syn-multi12  31 单元  匹配 50,038  Σdf 188,147   + schema / fix / server / token / Android / client
```

外壳是真实锚点 query `sr-a01`，所以单元数落在真实量级（22…31，`FTS_MAX_UNITS = 32` 封顶）。

## 3. 等价性：四项全过

| 项 | 口径 | 结果 |
| --- | --- | --- |
| **恒等锚点** | `minUnits = 1` 时 A / B / C(50) / C(200) 必须与生产 `searchObservationsFts` **逐条相同** | **139/139 一致** |
| **A ≡ B** | `minUnits = 2` 时 SQL `instr` 归因与逐单元 MATCH 探针必须逐条相同 | **139/139 一致** |
| **归因语义** | `instr(lower(col), unit)` vs `MATCH "unit"`（抽样：每 cohort 前 3 条 query × 页面前 3 行） | **0 处分歧** |
| **C 的截断损失** | C 相对 A 丢掉的记录 | **0 条 query 受影响** |

第一项是装置正确性的锚点：`minUnits = 1` 就是"没有覆盖度要求"，任何形状在那里都必须复现今天的页面。
第三项值得单独说：trigram 是子串语义，但 FTS5 的大小写折叠与 SQLite 的 `lower()` 实现不同，
**分歧必须被测到而不是被假设不存在**；抽样范围内没有分歧。

**第四项不可外推**，理由与 F0-1 同一条：它是在中文竞争池只有 66 行的语料上量的。
真实中文语料里，一条通过覆盖度的记录完全可能排在 `K` 之外。**必须在 F2 的中文装置上重测。**

## 4. V2 的 df 一遍成本：不是"很低"，是"约一倍基线"

plan §2 的 V2 行写着"一次分组 `COUNT` 即可拿到全部单元 df，成本低"。实测：逐单元 MATCH
`count(*)` 在最坏一格是 **99.27 ms**，与基线 105.47 ms 同量级，而不是可忽略。

原因是它必须**在整个 scope 上**数每个单元的 df——这与形状 C 的候选内归因不同，
无法只在 K 行上完成。所以 V2 的 arm 必须自带这份预算，判据里不能按"成本低"处理。

---

## 5. 对判据的输入（只有形状，没有取值）

1. **V1 的实现形状取 C**：在 FTS 腿内部取前 `K` 个 bm25 候选，在候选内归因并按覆盖度过滤，
   然后返回至多 50 条给内核。这样 **V4（返回内核的 50）保持冻结**，`K` 是 V1 自己的参数，
   两者不纠缠。
2. **A 不进网格**（成本 16.7× 基线）。**B 只作诊断对照**：它语义精确，可以在 F2 用来
   核对 C 的截断损失，但它的成本不与语料规模脱钩，不适合作实现。
3. **`K` 必须写进 V1 的定义**，并且每个 arm 必须报告**页面缩水**（因截断而少于 `limit` 的返回）。
   本探针已经看到该效应的极端形态：锚点 `sr-a25`（匹配 3,344 行）在 `minUnits = 2` 下
   **四种形状全部返回 0 行**——覆盖度可以把整页清空，这正是 plan §4.1 要求 G4 拦住的方向。
4. **V2 的 arm 要预留约一倍基线的 df 成本**。

## 6. 诚实边界

1. **本探针不是 arm**：不算任何门（G1–G4）、不算召回与误召回、不碰语义腿、不建向量。
   因此它不受 plan §3 第 6 条"没有中文语料不得跑 arm"的约束——那条约束的是 arm。
2. **`minUnits ∈ {1, 2}`、`K ∈ {50, 200}` 是固定刻度，不是候选取值。** V1 / V2 的取值刻度由 F1
   判据在新集上定，本报告任何数字**不得**作为取值来源（与 plan §3 第 7 条同一条纪律）。
3. **只有成本读数声称可外推**，理由是成本与语言无关（§2.1）。**`C 丢 0 条` 明确不可外推**（§3）。
4. **df 刻度不是等距曲线**：英文 filler 的 df 谱有断层，目标 25,000 与 10,000 都落到
   `layout = 6,670`，目标 200 落到 `index = 4`。这条不得当作 df 敏感性曲线读。
5. **单机单次读数**，非多次运行统计。`msMin` 是对调度抖动最稳健的下界，`p95` 含抖动；
   前面几次预跑里同一格的 p95 曾在 20 ms 与 221 ms 之间跳动，这就是为什么主读数用 `msMin`。
6. `FTS_COLUMNS` 与 F0 的 `pass1Units()` 同一条边界：它按 `src/db/schema.ts` 的表定义**重新声明**，
   生产列表改动后本探针的归因会失效，必须同步。
